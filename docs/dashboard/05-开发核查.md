# 大屏内网网站开发核查

核查日期：2026-09-10。对象：PR #13 合入的设计与方案，基准提交 `95e98849a5f450d10bf6485d16d803ed18b48a19`。方式：作者对照官方资料联网自审，并回读当前原型代码；不是独立第三方审核，不是现场测试。

## 1. 结论

现有“原生静态大屏＋内网状态服务＋PostgreSQL＋独立执行进程”的分工可以保留。频道规模不构成引入微服务、消息集群或云平台的理由；5秒轮询是本项目待实测的起始选择，不是行业强制频率。

原文已经覆盖日单版本、真实接收证据、幂等、任务租约、断线提示和离线依赖，但**还不足以直接当作完整的生产实施合同**。本次归纳10组遗漏或需要收紧的表述，已补入相应正文及 E19 方法。下面“已补充”只表示文档修正，相关能力仍需实现和验证。

## 2. 发现与处理

| 编号 | 原文问题及可能影响 | 依据与本项目处理 | 正文位置 |
|---|---|---|---|
| R01 浏览器时间与恢复 | 只写定时轮询及单调时间，不能覆盖后台节流、休眠和恢复旧页面；醒来可能继续播旧动画 | MDN 明确后台计时器会节流，performance.now 的休眠行为有平台差异。补恢复先取快照、双时钟异常检测、迟到响应废弃及过期先停动效 | 工程设计 5.1；产品需求 4；E19 |
| R02 数据库约束 | 同任务证据、accepted 时间和反馈空值虽有描述，但约束落地边界不够清楚；CHECK 不能用来查询另一表判断合法 | 明确本行 CHECK、外键和受控事务／触发器的职责；补证据撤销、日单选择的锁与序列、业务状态和观察状态分离 | 工程设计 3.4 |
| R03 权限与输入 | “内网／只读身份”过于概括；未约定认证失败、来源权限、字段／体积边界和转发头信任 | 端点逐项授权、来源身份绑定、限制日期／编号／payload，拒绝未知字段；网页与来源写入分别认证，不能将网段限制当成完整身份验证 | 工程设计 6.1；部署方案 3.1 |
| R04 浏览器渲染 | 原型拼接了部分 HTML 与内联样式；未来接外部事件时不能直接把源数据插进去，也不能机械启用会破坏页面的 CSP | 文本安全输出、状态／颜色白名单、同源资源策略；CSP 先在候选报告模式验证，处理内联样式兼容后启用 | 工程设计 6.1 |
| R05 资源和维护信息 | 未写连接池总预算、排队上限、长任务超时及磁盘压力；模型忙时可能拖垮状态页 | 为 API、worker、数据库和模型分别预算；有限队列、退避、超时与停领规则；保留内网诊断信息但不新增产品 KPI | 工程设计 4.1；部署方案 3.2 |
| R06 服务生命周期 | 只列启动顺序和重启策略，容易误认为“容器正在运行”等于可用，或 unhealthy 会自动重启 | Compose 就绪条件与应用重连分开；进程退出重启、活着但卡住的诊断／恢复、优雅停止分别定义 | 部署方案 3.2；E13/E19 |
| R07 离线包可信与补丁 | 只有包内摘要，无法证明整个包来自批准构建；断网后也仍需补丁维护 | 可信发布身份签名清单、预置验证公钥、离线验证工具与依赖清单；漏洞资料和补丁由构建侧带入，不现场联网 | 部署方案 5、6 |
| R08 备份一致性 | “每日备份＋日志归档”不够精确；pg_dump 不能直接作为 WAL 重放的基础，数据库与外置文件也不能各自随便取时点 | 区分逻辑恢复与物理备份/PITR；记录一致的文件集合和数据库备份身份，恢复后先核对再开 worker | 部署方案 7.1 |
| R09 容器网络边界 | 只写限制端口，未提醒 Docker 发布端口可能绕过 UFW 的预期规则 | 只发布网站入口，数据库和 API 不直接暴露；按实际 Docker 网络后端从允许及不允许终端验证，而非只看防火墙配置 | 部署方案 3.1 |
| R10 无人值守与可读性 | 现有暂停仅针对动画，减少动态未自动关闭轮播；颜色、低透明度与4K缩放也未等于可访问性验收 | 补开机启动、休眠恢复、显示器断连、长时运行测试；区分动画暂停和数据实时性，颜色有文字／形状补充，测最暗帧与故障闪烁；不改已确认原型 | 产品需求 4、8；设计基线 6；E19 |

## 3. 直接来源与适用范围

以下均为一手文档。来源证明具体平台行为或提供评估准则；本文的模块选择、轮询周期、容量预算与实施顺序是结合锦书范围作出的工程判断，不是这些机构对锦书的认证或采购建议。

| 来源 | 本次核实的事实／准则 |
|---|---|
| [MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[Performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now) | 后台节流与休眠计时差异；不能用网页定时器证明后台仍在工作 |
| [PostgreSQL 17 约束](https://www.postgresql.org/docs/17/ddl-constraints.html) | CHECK 的空值和跨行限制；跨表身份宜用外键，特殊状态关系还需事务机制 |
| [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html) | 私有接口也要做端点授权、类型／大小验证及安全错误响应 |
| [OWASP CSP](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html) | CSP 是附加防护，可先报告模式验证；不是安全输出的替代 |
| [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) | 记录必要的故障与安全事件，同时排除凭据和敏感内容 |
| [Psycopg 连接池](https://www.psycopg.org/psycopg3/docs/advanced/pool.html) | 连接池有上限、等待和重连行为；多个进程的连接预算必须一起算 |
| [Docker 资源限制](https://docs.docker.com/engine/containers/resource_constraints/) | 容器默认不会自动获得合理的 CPU／内存上限 |
| [Compose 启动顺序](https://docs.docker.com/compose/how-tos/startup-order/)、[Docker 重启策略](https://docs.docker.com/engine/containers/start-containers-automatically/) | 启动顺序不等于就绪；重启策略针对容器退出，与健康检查信号不同 |
| [SLSA 制品验证](https://slsa.dev/spec/v1.2/verifying-artifacts) | 验证需把制品摘要和可信构建／签名身份结合，不能只信包内自述 |

| [W3C 暂停／停止](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)、[闪烁阈值](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html) | 持续动态、自动更新与闪烁分别评估，不能只设置一个微闪周期就宣称通过 |
| [W3C 颜色](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)、[对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 颜色不能是唯一识别方式；文字对比需要测量，不由截图观感替代 |

## 4. 可以保留和不应扩大之处

保留原生 HTML/SVG、模块化单体、独立 worker、事务数据库、只读大屏与同源供数、5秒起始轮询、单主写入和人工接管方向。没有发现必须改成 React、WebSocket、Kubernetes 或云端服务的项目理由；新增依赖必须对应当前问题。

不把网站核查变成后台全面开工、采购或现场网络变更；不新增运营管理平台、账号管理页面、自动播控或外部告警服务。安全和运行约束只为当前内网状态网站建立可验证边界，具体脚本／配置随后续实现交付。

## 5. 仍需取得的证据

- 实际浏览器、4K屏幕与观看距离下的编号、颜色和长期展示表现；原型尚不能认领完整可访问性符合性。
- 人工接手／完成与 Playbox 接收的现场证据来源，频道和文件身份规则。
- 20／40频道、实际并发任务与观看终端数量下的 API 延迟、连接池和模型资源预算；文档不能推算实际容量。
- 无缓存离线安装、可信包验证、证书到期处置、数据库／文件恢复与单主接管演练。
