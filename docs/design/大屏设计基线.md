# 大屏设计基线

版本：v1.0｜2026-09-10｜产品负责人确认的展示设计。本文记录已有外观；真实接入的增量要求见[状态协同需求](../product/02-大屏驱动的状态协同需求.md)。

## 1. 唯一设计与代码入口

可运行的设计原型就是 [src/dashboard/dist/index.html](../../src/dashboard/dist/index.html)，启动方式见[大屏说明](../../src/dashboard/README.md)。不另存一份独立 HTML，以免改动后出现两套样式。`dist/` 在这个无构建步骤的原型中是直接维护并提交的静态源码目录，不是可以随手删除的缓存。

| 文件 | 职责 |
|---|---|
| [index.html](../../src/dashboard/dist/index.html) | 页面分区、名称、标签与容器 |
| [styles.css](../../src/dashboard/dist/styles.css) | 深浅主题、C 双环、微闪与线条样式 |
| [app.js](../../src/dashboard/dist/app.js) | 布局、编号连线、日期轮播与渲染 |
| [model.js](../../src/dashboard/dist/model.js) | 虚构任务、六态与演示推进，不是生产调度器 |
| [assets/](../../src/dashboard/dist/assets/) | 本地 StarTimes 公司 Logo、原创锦书标识 |
| [模型检查](../../tests/dashboard-model.test.cjs) | 日期、任务状态、路径与工作动效规则 |

基线来源：[PR #10](https://github.com/Moshuiwang/jinshu/pull/10)、[PR #11](https://github.com/Moshuiwang/jinshu/pull/11)。后者合入版本为 `28d64346f03b83229cafcb818f45af828ec54b1b`。后续版本继续修改这套源码并通过 Git 追溯，不复制带日期的 HTML。早期被替代的图稿和样式试验不作为现行交付物。

## 2. 观众与信息层级

工作流和人机交接是唯一主视觉。领导能看懂工作正向前推进，同事能判断 Agent 是否在工作，审核岗位能识别哪些频道已经到编单员手上、哪些需要关注。大屏只读、无声音、平时无需操作，不加入详情弹窗、人员姓名或编单修改入口。

| 层级 | 内容 | 位置 |
|---|---|---|
| 主视觉 | 六个横向节点、频道编号、当前状态与流动 | 画面中部绝大部分面积 |
| 主信息 | 播出日期、完成数量、故障及超时提示 | 工作流上方紧凑一行 |
| 辅助 | 公司及系统标识、名称、版本、当前日期时间 | 顶栏 |
| 辅助 | 状态图例、最终文件回读对比概况 | 工作流下方 |
| 查号 | 001—020 与频道名称的对应 | 底部两行图例 |
| 运行说明 | 演示标记、最近事件、最近更新 | 页脚 |

外部名称“四达传媒智能编单系统”；内部名称“锦书”。公司使用 StarTimes 原始标识，锦书标识表达书册、编织与编排，来源见大屏说明。不依赖外网图片地址。

## 3. 布局与日期

- 按 4K、16:9 规划；当前 HTML/SVG 使用 1920×1080 逻辑坐标，在 3840×2160 屏幕按两倍绘制，其他窗口等比适配，保持全屏无滚动。
- 顶栏紧凑，不设置大标题留白区。现行主图标 68px、节点标题 22px、频道圆圈 44px，均为逻辑尺寸；正文系统字体由设备提供。
- 标签依次为“汇总、今天、明天、后天”。按播出日期分组，默认明天；每 30 秒轮播三个日期。汇总只保留禁用标签，不进入轮播；历史数据不占主画面。
- 六个节点：EPG 接收 → 素材匹配 → 智能编排 → 检查产出 → 编单员 → Playbox 已接收。四个 Agent 节点是共享职责，不等于后台必须有四个进程或四个模型。
- 首批仅显示 Playbox 的 20 个频道。每个节点都放完整编号槽位，频道号三位补零。竖向有序、横向交错，避免整体倾斜；节点内部的圆圈之间不连线。
- 扩为 40 频道时复用同一数据与组件结构，槽位从两列扩为四列，底部名称从两行扩为四行。编号是稳定身份，颜色可复用，不能靠颜色识别频道。实际远距辨识仍需现场验收。

## 4. 圆圈与连线

采用 C“双环留白”：外圈表达处理结果，内部与微闪表达当前位置。编号文字保持稳定可读。

| 数据状态 | 圆圈 | 语义 |
|---|---|---|
| unused | 灰圈灰心 | 从未走入 |
| passed | 绿圈灰心 | 正确通过；终点为确认接收 |
| warning | 橙圈灰心 | 有告警但允许通过 |
| rollback | 红圈灰心、较急促闪烁 | 故障位置保留，任务已回到上一节点 |
| processing | 频道色圈和内心、轻微闪烁 | 当前处理位置 |
| fault | 红圈红心、较急促闪烁 | 故障仍停留在本节点 |

正常处理使用蓝、青蓝、紫色，与绿／橙／红结果色分开。浅色通过绿 `#21845b`，深色通过绿 `#69c79b`；浅色故障红 `#d94355`，深色故障红 `#ef7686`，其他颜色以样式源码为准。

跨节点只连接相邻节点的同一频道，线条无箭头：

| 路径 | 表现 |
|---|---|
| 已走完 | 淡绿色静态线永久保留在当前任务视图，不再生成移动光点；告警通过也计作走完，告警由橙圈保留 |
| 正在运行 | 细线及单颗光点跟随底部频道图标色 |
| 故障停留 | 红色静态线，不再向前移动 |
| 已回退 | 红线，单颗光点反向；恢复事件到达后改为实际执行方向 |

已完成线的透明度目前浅色 0.16、深色 0.27，弱于运行段。处理槽位微闪周期 2.6 秒；工作中的 Agent 图标 2.8 秒；故障约 0.68 秒。不整屏闪烁、不闪数字。暂停动效或系统减少动态偏好会停止动画，但保留所有状态、线条和文字。Agent 在等待、空闲或仅有故障时不微闪；有其他正在执行的任务时仍微闪。

## 5. 原型与真实版本的界线

目前三日任务都是虚构记录，刷新会重新生成；状态每 8 秒模拟推进。静态页面无需数据库、在线 AI 或网站托管服务。此设计已能演示，不代表真实 Agent、持久化、内网服务安装或 Playbox 回执已实现。

真实版本沿用本外观，新增“来源未接入、状态待确认、数据中断”的简短文字与停动画处理，不能把未知画成从未使用，不能断线后继续模拟推进。产品口径由[状态协同需求](../product/02-大屏驱动的状态协同需求.md)负责；数据库、模块与部署分别见[工程设计](../engineering/大屏状态服务与数据库设计.md)和[内网部署方案](../../deploy/README.md)。
