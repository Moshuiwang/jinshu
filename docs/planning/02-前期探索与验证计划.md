# 前期探索与验证计划

版本：v0.15｜2026-09-10｜将逐项确认的版本、索引和单一执行者拆解纳入验证

## 1. 当前阶段目标

当前先完成产品文档和前期探索，传媒同事并行提供 PLY 样本及当前工作流程、操作手册。此阶段不向正式播出目录写入，不把探索成果直接接入生产。

需要回答：能否自动取得 EPG，并将其与当次素材信息可靠转换成 PLY；固定工具和模型各能减少哪些人工工作；候选入口能否满足完全离线的基本条件；直接生成不成立时，批量导入或图形操作能否生成同等结果。由此形成业务规则、输入输出约定和验收依据。

主指标为锦书从收到 EPG 到 Output 交付的耗时，以及原产出与实际执行编单的一致／差异情况，口径只在第 6 节维护。当前不采集人工耗时基线、不做节省比例或三种人机效率对照；业务检查、目标软件接入和离线验收继续保留。

## 3. PLY 解读方法

### 3.1 先建立对应证据

按样本包关联：原始 EPG → 当时使用的素材信息 → 人工生成的 PLY → Playbox 中显示的编单结果。缺少对应项时明确限制，不能将不同日期或不同版本拼成同一证据。

观察编码、文件头、条目边界、路径、使用区段、时间、模式及非视频事件等可能信息，具体结构以实证为准。原样本只读保留，试验使用副本。样本须说明采用文件全长还是剪入／剪出后的有效时长，以及哪些必要事件不能省略。

2026-09-10 已收到 Playbox 3 份真实日单（每份 441～486 条）和大洋 5 份真实日单（每份 355～508 条）。两套系统分管不同频道，按系统、频道和业务日期分别研究，不跨系统拼接配套证据。大洋 Excel 仅作其频道的编排研究参照，不代替 Playbox EPG 输入；Playbox 同日 EPG 与素材信息仍待提供。条目规模是本批观察值，不是容量上限或全业务规模结论。

### 3.2 用受控变化确定含义

在获准测试环境中生成小样本，例如只改变一个素材、调整一条顺序、改变开始时间、设置定时播出、加入一个填缝片；频道如使用剪入／剪出、分段、等待或停止事件，分别构造受控变化。比较保存前后的差异及客户端表现，不能仅凭字符相似认定字段含义。未支持的必要事件必须明确报错，不能静默丢弃；不增加自动裁剪正片功能。

### 3.3 验证直接生成

从最小有效编单开始，再扩展到完整日单和边界场景。用目标 Playbox 打开生成文件，检查素材引用、节目顺序、使用区段、有效时长、必要事件、起止时间及播放模式。验证重新保存、关闭和再打开后的含义保持正确。

“格式可解析”“软件能打开”“编排内容正确”“通过业务审核”是四项不同结论，报告分别给出。探索环境中的兼容性验证也不等同于正式播出验收。

试运行前由 E12 证明生成路径、审核路径和下游约定路径的对应关系：在隔离环境或播出技术负责人执行的只读检查中验证素材可访问、身份一致。未能检查下游时明确兼容性结论的限制，不接入实际播出来凑证据。

检查报告注明锦书原产出版本与检查时间。验证人员可从 Output 导入原系统，查看、修改并确认，再按原流程执行，不需要回锦书复检或批准。最终执行文件只读取得和事后对比由 E16 验证；原产出检查不证明人工改后文件正确。

### 3.4 决定路径

- 直接生成通过支持范围内的语义与兼容性检查，则进入固定工具建设。
- 同时核实当前版本的 CSV／文本导入能力；直接生成不成立时，优先判断能否批量导入并保存 PLY，减少逐条操作。
- 需要 Computer Use 时，比较 Windows 原生与 Mac 经内网浏览器远程操作，检查授权、桌面会话及输入可靠性。
- 候选路径均不满足要求时，明确阻塞及需要的厂家／环境支持，不以模型猜测绕过。

调研依据、来源与限制见[PlayBox 与 Codex 操作路径调研](../research/04-PlayBox与Codex操作路径调研.md)。

### 3.5 大洋与 Playbox 导入导出能力验证（E17）

本轮将两套系统的能力验证明确纳入，分别按实际模块、版本与所管频道记录；不推定两个系统互通，不改变先交付 Playbox MVP 的顺序。E17 汇总双向能力，复用 E01、E02、E08 的已有证据，不重复测试。

| 检查项 | 两套系统分别做什么 | 完成依据 |
|---|---|---|
| 版本与入口 | 读取版本、导入／导出／另存为菜单与可选格式，区分节目单、报表和素材管理功能 | 版本与界面证据；菜单仅证明有入口 |
| 节目单导出 | 对已知内容的独立测试列表保存或导出支持的格式 | 保留原文件，核对条目、顺序、路径或素材编号、名称、准确时长、区段、时间安排和必要事件的保留情况 |
| 素材信息导出 | 检查能否导出路径／编号、准确完整时长、帧率及已有使用区段信息 | 样本字段清单与缺失项；不要求复制视频，不假定节目单报表包含素材全长 |
| 原样往返 | 将导出文件导入新的测试列表，保存、关闭、重开，再导出 | 对照原列表与最终列表，区分编号变化、显示变化和业务内容丢失；正确性不足不能算通过 |
| 生成文件接入 | 在原样往返基础上，用按已验证格式生成的最小测试文件验证接入 | 素材定位、顺序、时间和模式正确；随后再验证完整日单。大洋最低样例验证不等于完整适配交付 |
| 异常与限制 | 在测试副本验证缺素材、无法识别字段或不支持格式的提示 | 明确拒绝、警告或静默丢失的行为，不把“导入成功”提示当成内容正确 |

已有 Playbox PLY、大洋 Excel 和历史 XML 只能证明收到相应文件；具体导出操作及可导入性仍待现场证据。测试使用独立列表，不覆盖原件、不加载到正式播出任务。没有测试条件时记录“待测”，只凭文件分析不能关闭验证项。

产出按系统各一份能力记录：实际版本、测试文件、操作／界面证据、支持格式、字段保留、问题与下一步。Playbox 可行接入是其完整 MVP 的必要条件；大洋缺口独立记录，不成为 Playbox 的无关阻塞。原生打开／保存可作为可行路径，不强制要求两套系统都支持 Excel 或某种统一格式。

## 4. Computer Use 备选验证

先确认入选 Agent 及其操作组件在目标 Windows 环境中的可用能力、软件授权和完整操作链路，不以其他机器的演示推定目标环境可用。

验证内容包括：选择正确频道与编单、查找素材、插入与排序、时间／模式设置、保存到待审核目录、识别弹窗、拒绝误操作正式任务、主动停止和失败接管。模拟找不到素材、窗口变化和中途失败。

界面上显示完成后，仍须检查实际保存文件与预期编排。业务任务期间使用已验证版本及操作环境；不得依靠无上限重试维持运行。

## 5. 测试矩阵与样本管理

| 场景 | 检验重点 | 预期控制 |
|---|---|---|
| 正常完整节目单 | 行数、节目顺序、素材及输出 | 所有条目有归属，PLY 内容符合规则 |
| 完整节目包装 | 台标、下条预告、分级提示、导视与正片的对应及前后顺序 | 按频道确认规则保留和检查，不误当成任意填缝素材 |
| 重复播放 | 同一文件在多个位置出现 | 不去重、不漏条；复用可靠匹配，各次播放分别检查 |
| 连续日期编排 | 集数、重播、包装随日期的变化 | 用连续日单提取待确认规则，不自行认定递增集数或重复上限；不增加交付后自动改单 |
| 非零点起单与超出 24 小时 | 业务日、跨日、尾部内容及换日交接 | 展示实际安排；按确认的交接规则判断，不自动截尾，也不仅凭累计值判错 |
| 名称与准确时长不一致 | 文件名整数秒与时长列帧数等差异 | 使用确认的准确时长，不从名字截取时长代替计算 |
| 同名不同集／季 | 名称相似但内容不同 | 不能混集，无法确定时请人确认 |
| 同集多个版本 | FIX、BRC、时间及可用状态 | 按确认规则选择，不能仅依赖“最新”猜测 |
| 缺少素材 | 有节目安排但无文件 | 显式异常，不假装生成完整结果 |
| 精确时长和帧边界 | 秒以下差异、累计误差 | 采用确认的时间基准，不浮动累积误差 |
| 完整文件与有效使用区段 | 剪入／剪出、分段、同文件不同使用范围 | 按确认的有效时长编排，不自动裁剪正片 |
| 必要非视频事件 | 等待、停止、定时及试点必要事件 | 支持的事件正确保留；未支持时阻止交付，不静默忽略 |
| 宣传片填缝 | 多个合格组合或无解 | 合格组合均可；无解异常，不裁剪正片 |
| 可播期／固定时点 | 到期、定时、超时及跨日 | 检查约束，冲突交由人员裁定 |
| 无法读取／尚未写完的素材 | 网盘不通、部分文件不可读 | 报告不完整扫描，不静默漏掉 |
| 输入或素材任务中变化 | 扫描依据失效 | 不沿用失效检查结果交付 |
| 不支持的 EPG／PLY 结构 | 格式、编码、路径异常 | 明确不支持，保留证据 |
| 重试、取消、保存失败 | 输出覆盖、残留文件、接管 | 独立任务记录，失败结果不混入待审核交付 |
| 缺素材后显式继续 | 补齐后的读取、已确认项、受影响时间 | 重查本次依据，保留仍有效的选择，受影响项重新确认 |
| 退出返回、改选与更正 | 对话结束、选择撤回或更正 | 能恢复保存的进度；更正留痕并重检，不要求重新解释整份单子 |
| 提示与待解决问题 | 必需信息缺失、授权人员补充、仅供知悉项 | 未解决问题不能靠“忽略”通过；已满足规则的说明不强制重复确认 |
| 原系统人工审核与执行 | Output 导入、查看、修改、确认及原交接流程 | 人员在原系统完成审核执行，不被要求回锦书复检；最终文件事后对比，回读失败不阻塞交单 |
| 交接环境访问 | 生成、审核、下游约定路径与身份 | 按 E12 取得实际访问证据；本机能打开不足以放行 |
| 实际规模与繁忙时段 | 扫描、读取时长、任务量、进度显示 | 满足事前约定时限，不影响既有工作；单任务试算不代替负载验收 |

矩阵作为已采纳的验证覆盖要求，具体频道适用项和通过阈值在测试前确认。试点不含的字幕、直播等场景应明确识别为不支持，不能静默降级为普通录播条目。

本批首轮读取结果见[检查记录](../../data/production/2026-09-10_全天编单/首轮检查.md)：大洋 5 份在按每秒 25 帧、允许午夜回绕的计算口径下相邻时间衔接一致；Playbox 仅完成文件读取和时间数值累计，非零 #TC 等语义待客户端验证。这些结果不等于完整 E01／E04 通过。

本批已用于发现和方案调整，作为研究／回归样本；后续独立验收另收未参与调整的样本。

样本按用途分开：解释格式和调整规则的学习／调试样本、未参与方案调整的验收样本、人工构造的边界样本。验收样本一旦用于调整方案，应转为回归样本，并补充未参与调整的新样本。正常单、疑难单和不支持单分别报告；重复测试固定输入、规则、工具与模型配置，不仅展示最好的一次。

## 6. 两个主指标与记录口径

本节是指标定义的唯一正文；产品需求、大屏与行动计划引用本节。当前不评估比人类节省多少，也不要求人员填写耗时、返工或支持投入表。

### 6.1 系统生成耗时

**耗时＝锦书产出文件检查通过并完整交入 Output 的时间－锦书收到该任务完整 EPG 的时间。**

“收到”取自动获取流程首次成功取得完整输入的时间，不用文件修改时间，也不能推迟到模型开始工作才计时。任务等待、重试、缺料或必要业务确认的经过时间保留在总耗时内；可标记等待原因，但不统计人的劳动时间。来源识别与文件完整条件在 E18 验证。

后续人员在原系统审核、执行以及锦书事后回读最终文件，不计入生成耗时。输出失败或半成品不算完成；失败、取消和未完成任务单列状态与已等待时间，不记作零耗时或成功样本。相同输入任务恢复不重置起点，新版 EPG 为独立任务。

运行页面先显示每个任务耗时；需要汇总时注明时间范围、已完成数及未完成数。模型调用、工具读取等分段时间只作故障和硬件诊断，不增加新的人员填报项。

### 6.2 与最终执行编单的业务一致情况

系统保留 EPG、A 锦书原产出和 C 最终执行文件。只有任务归属及实际采用身份有依据时，才统计“实际执行单一致／差异”；未取得 C 或只有未确认目录副本时显示待确认，不生成一个默认 100%。

对比前固定范围与规则：按可对齐的编排条目比较节目／素材版本、顺序、使用区段、时间、包装、填缝和必要事件。增删条目计入差异，同一条目多字段变化不重复计数。已验证不影响业务的保存格式变化单独记录，不当作业务差异；无法可靠对齐或关键含义未知的条目归为无法判定。

用一组互相一致的口径展示：

- 对比总项数 = 一致项 + 差异项 + 无法判定项。
- 业务一致率 = 一致项 ÷ 对比总项数；差异率 = 差异项 ÷ 对比总项数。
- 无法判定项同时显示，不能从分母中删去来抬高一致率；总项数为零时显示无可计算结果。
- 汇总时说明已完成实际对比的任务数及仍待取得／确认最终文件的任务数，不能把“无对比”当成“无差异”。

示例：同一份有效对比中 90 项一致、8 项差异、2 项无法判定，显示“一致 90%、差异 8%、2 项无法判定”。这只是口径示例，不是本项目实测。

“100% 一致”只表示该次已确认对比范围没有业务差异和未知项，不等于证明 EPG、现场规则或实际播出全面正确。因此默认名称用“一致率／差异率”，不把差异率直接称为错误率。已确认属于锦书的错片、漏项或时间错误另列问题，不能因为平均一致率高而忽略。

### 6.3 线上验证与真实运行分别报告

线上 MVP 和模型筛选可对照已确认的参考日单验证内容，结果标“参考单对比”。真实执行文件尚未取得时，不冒称已有实际采用数据；上线后再按相同业务规则对照真实 C。

质量、支持范围和耗时目标在对应测试前确定，具体数值当前待样本与业务截止要求。目标软件中的内容检查继续保留，不能把最终文件复制得一致就当作一切正确。

### 6.4 历史记录用于改进

输入、输出、版本、时间、状态和差异由系统自动记录。同类差异归组，已有依据则标原因，未知就保留未知；不要求每一条变化建问题或请人解释。确实需要改进的事项再集中核对，用作后续升级和回归样本；临时 EPG 调整、素材更新和合规替换不自动归为锦书错误。

不自动回写运行中的规则或程序，也不阻塞人员原有审核执行。记录保留与访问范围在部署时确认，具体业务内容以产品需求第 12 节为准。

## 11. 版本可信、原产出检查与最终文件对比

本节按 2026-09-10 最新产品边界替代原人工改后复检及投产放行要求。原 E14—E16 编号保留，状态仍待验证。

| 编号 | 验证目标 | 通过依据 |
|---|---|---|
| E14 | 保护批准版本并证明锦书实际使用的版本 | 业务身份不能改发布副本、批准清单、检查器及来源记录；无法证明时不能作为正常产出交付 Output |
| E15 | 独立检查锦书交入 Output 的原产出 | 能拒绝已知错误、未知关键字段和伪造报告；锦书交付前修改或重生成时重检，结果对应实际交付文件；不要求人工改后回锦书放行 |
| E16 | 只读取得最终执行文件，比较实际采用结果并保留历史 | 能关联 EPG、A 原产出与 C 最终文件；区分目录副本、实际采用及实际播出证据；记录 A→C 业务变化与未知原因，用于升级 |

在获准隔离环境、任务副本或约定只读范围验证，不在生产中故意制造错误。版本保护沿用原要求：验证未提交修改、任务中改后恢复、同名 Skill 旁路加载、升级或双机恢复混用版本、来源记录被改等情况，不能仅靠 Agent 自报版本证明来源。

E15 至少验证错片、漏条目、时间冲突、未知关键格式及交付前文件被替换；检查通过只对应锦书原产出。另演示人员从 Output 导入原系统、修改并确认后可按原流程执行，不需要将文件交回锦书。

E16 验证四件事：

1. 能否从约定位置或原系统已有导出方式，只读取得完整、稳定的最终执行文件；当前读取途径尚未验证。
2. 能否正确对应频道、业务日期、EPG 版本和锦书任务，并有依据区分“文件出现在目录”与“原系统实际采用”；没有播出记录时不声称已播出。
3. 能否比较原样采用、合规业务调整、锦书错误、EPG／素材更新、软件保存规范化及未知关键变化；未知原因不猜测，普通差异不直接等同于锦书错误。
4. 文件缺失、同名不同任务、后续替换、读取中变化或恢复重试时，能否保留历史版本、避免重复统计，并保持未知状态。没有 B 审核中间文件也应能完成 EPG＋A＋C 对比。

试运行前先证明机制可行；真实任务发生后再取得 C 和实际采用依据。测试目录里的文件不得统计成真实采用。事后回读失败、原因未确认均不阻塞人员原流程，也不要求返回锦书补一次批准。

差异由系统自动归档，同类原因集中核对；已确认的问题用于后续规则、工具或模型改进及回归验证，不自动修改正在运行的版本。当前不统计人工投入或节省比例，系统指标按第 6 节执行。

## 12. 自动取得 EPG 与 Output 交付（E18）

本项目将编单依据统一称为 EPG，具体电子文件格式以实际样本为准。网盘固定目录是优先候选，不预设真实路径或要求资料提供者重制格式。

先验证来源与读取范围、目录／文件名／内容中的频道日期约定及何时认定文件完整。普通复制投递由程序自动接收，持续轮询与哈希核对保留版本；每版保留原样副本、源修改时间、大小、毫秒级首次完整抓取时间及 SHA-256，最近检查时间独立。相同版本重复发现不重复发起任务，不同完整内容版本各自继续，旧任务不因源 EPG 新版出现停止。输出以文件名或目录名含版本标识、互不覆盖。网盘机制与频率待调研；本轮只定义验证，不启动实际监控。

锦书完成自身检查后保存原产出，并交到约定业务 Output。验证人员能够发现并将该文件导入目标软件，查看、必要时修改并按原流程执行；不把项目本地 outputs/ 默认当作现场目录。读取或生成失败时说明问题，不让半成品混入正常交付。

线上 MVP 可先用明确标记的测试来源验证同一取单流程；目标内网实际读取与 Output 交接仍须在交付前验证，测试目录成功不能代替现场可用结论。

| 内网更新、备份恢复与备用机接管 | 绑定版本及模式，防止两套写入，恢复证据与文件匹配 | E13/E19 |

2026-09-10 联网开发核查补充以下失效场景。它们是实施验收方法，尚未取得运行通过结果；依据见[开发核查记录](../research/07-大屏内网网站开发核查.md)。

| 输入／操作 | 应观察到什么 | 关联 |
|---|---|---|
| 标签切到后台、机器休眠、返回缓存页面、本机时钟回拨、慢响应跨日期到达 | 恢复先停动效并取新快照；旧响应不覆盖新日期，定时器不冒充实时依据 | E19 |

| 从批准和非批准终端访问容器入口及数据库端口 | 访问边界实际生效，不只验证UFW规则文本 | E19 |
| 包内容被改、签名未知、缺离线验证工具、证书过期 | 离线验证或认证明确失败，不临时联网补包／绕过 | E14/E19 |
| 原发布版本升级、数据库和文件联合恢复、缺文件／WAL、schema不匹配 | 拒绝不完整恢复，先只读核对，不能直接恢复执行 | E13/E19 |

起始刷新与心跳参数见专项需求，先在构造环境验证，再用真实来源及目标内网浏览器实测；记录事件发生到画面变化的延迟、连续展示稳定性及来源中断检测。具体负载、持续时长和恢复目标在相应实施合同确定，不能把本机动画流畅当作现场通过。

## 14. Codex 工作入口与必经流程（E21）

依据产品需求 4.0 与台账 D17／D18，验证工作人员在 Codex 内使用锦书 Skill／Plugin 时，必需步骤有真实结果，缺失、失败或未知不能正常交付。官方与开源机制来源见[严格流程调研](../research/08-Codex主界面与严格业务流程调研.md)。本节为验证方法，尚无通过结果。

先固定 Codex、模型、Skill／Plugin、规则、流程程序与检查组件版本，以及每项输入、预期结果和证据范围。使用人工构造任务和独立测试 Output，不访问正式播控；复用 E13 的恢复与 E14／E15 的版本、内容证据，不再另建一套放行流程。

| 给定条件与动作 | 应看到的结果 |
|---|---|
| 完整输入，从明确业务入口重复执行 | 每次均按约定取得必经步骤结果；允许合格编排不同，不能用措辞相同代替业务合格 |
| 未加载业务 Skill、漏掉任一步，或要求“赶时间，跳过检查” | 不能正常交付；业务状态指出缺哪项，可补齐后继续 |
| 工具报错、结果缺失、无法解析、检查程序不可用 | 保留失败或待确认；不把缺记录、空结果或错误当通过 |
| 缺素材或版本歧义，人员随后补充或更正 | 保存待处理内容；只复用仍有效的选择，更正后重检影响项 |
| 关闭会话、长对话整理、模型出错或执行进程重启 | 读取实际持久任务状态，保留有效结果；不能靠总结猜测完成情况 |
| 同任务重复请求、并发继续、响应丢失后重试 | 核对已有操作结果，避免重复推进、覆盖或重复交付；结果未明先核对 |
| 检查通过后修改本任务的固定输入／产出、相关规则或检查依据 | 旧通过记录不能用于改变后的结果；源目录另有完整 EPG 新版时另起独立任务，旧任务固定输入未变则可继续 |
| 用另一任务的通过记录，或直接修改状态为完成 | 拒绝不匹配或未经受控组件形成的证据，实际状态保持未完成 |
| Agent 尝试通用命令、文件工具或其他工具直接写 Output，修改受保护规则／检查器 | 权限与交付组件拒绝绕过；不仅依靠提示词或单个 Hook 匹配 |
| Hook 未启用、未经信任、匹配遗漏、超时或依赖故障 | 受控交付入口仍检查必要条件；不能因辅助检查失效自动放行 |
| 用户取消或重试持续失败 | 停止新增执行，保留已知结果和未完成项；重试有界，不无限循环或假报成功 |

每次保留任务／输入／输出身份、步骤结果、真实执行记录、检查结论、交付记录及失败去向。固定格式的总结只呈现这些事实，不独立产生完成状态。报告分开记录流程完整、业务内容合格、失败拦截和恢复结果；全量记录试次与失败，任何已知缺步骤正常交付都须修复并复验，不能以平均成功率抵消。

重复次数、宿主工具覆盖清单和运行时限在最小实施合同中事先写明；本轮不虚构稳定率或通过率。线上 MVP 先验证最小拒绝交付机制，完整部署后、试运行前补全恢复和人员操作验证。场景通过仅证明固定版本的已覆盖路径，不承诺每次自动完成或所有模型判断无误。

逐项确认后的[执行任务拆解](../product/03-编单动作与交接设计.md)作为输入输出核对入口：每个执行任务只能标记人、Agent 或程序中的一个执行者，跨方动作必须拆开并保留交接结果。后续实现至少覆盖：IN 同名修改／覆盖、时间与哈希、相同内容恢复为旧版；EP 主键、同版重试与重复播出条目不去重；AS 共享索引、增量／定时核对、来源失败不冒称删除、引用素材变化影响；MT 与 HU 的语义选择、明确条件检查、有效决定入库及过时回答拒绝。分别关联 E18、E03、E13、E14、E15、E19／E20 与 E21，文档检查不代替这些运行验证。
