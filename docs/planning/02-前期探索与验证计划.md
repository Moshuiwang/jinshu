# 前期探索与验证计划

版本：v0.9｜2026-09-10｜明确线上 MVP、模型能力与速度筛选、采购及本地验收顺序

## 1. 当前阶段目标

当前先完成产品文档和前期探索，传媒同事并行提供 PLY 样本及当前工作流程、操作手册。此阶段不向正式播出目录写入，不把探索成果直接接入生产。

需要回答：能否将 Excel 和当次素材信息可靠转换成 PLY；固定工具和模型各能减少哪些人工工作；候选入口能否满足完全离线的基本条件；直接生成不成立时，批量导入或图形操作能否生成同等结果。由此形成业务规则、输入输出约定和验收依据。

探索阶段不设节省比例，但从第一组配套样本开始记录人工投入。推广前必须证明包含确认、审核和返工的人工总投入下降；具体降幅在取得基线后、相应测试开始前确认。常规录播作为首期代表范围已由产品负责人确认，具体频道及人员后续提供。

## 3. PLY 解读方法

### 3.1 先建立对应证据

按样本包关联：原始 Excel → 当时使用的素材信息 → 人工生成的 PLY → Playbox 中显示的编单结果。缺少对应项时明确限制，不能将不同日期或不同版本拼成同一证据。

观察编码、文件头、条目边界、路径、使用区段、时间、模式及非视频事件等可能信息，具体结构以实证为准。原样本只读保留，试验使用副本。样本须说明采用文件全长还是剪入／剪出后的有效时长，以及哪些必要事件不能省略。

2026-09-10 已收到 Playbox 3 份真实日单（每份 441～486 条）和大洋 5 份真实日单（每份 355～508 条）。两套系统分管不同频道，按系统、频道和业务日期分别研究，不跨系统拼接配套证据。大洋 Excel 仅作其频道的编排研究参照，不代替 Playbox 初版输入；Playbox 同日初版表与素材信息仍待提供。条目规模是本批观察值，不是容量上限或全业务规模结论。

### 3.2 用受控变化确定含义

在获准测试环境中生成小样本，例如只改变一个素材、调整一条顺序、改变开始时间、设置定时播出、加入一个填缝片；频道如使用剪入／剪出、分段、等待或停止事件，分别构造受控变化。比较保存前后的差异及客户端表现，不能仅凭字符相似认定字段含义。未支持的必要事件必须明确报错，不能静默丢弃；不增加自动裁剪正片功能。

### 3.3 验证直接生成

从最小有效编单开始，再扩展到完整日单和边界场景。用目标 Playbox 打开生成文件，检查素材引用、节目顺序、使用区段、有效时长、必要事件、起止时间及播放模式。验证重新保存、关闭和再打开后的含义保持正确。

“格式可解析”“软件能打开”“编排内容正确”“通过业务审核”是四项不同结论，报告分别给出。探索环境中的兼容性验证也不等同于正式播出验收。

试运行前由 E12 证明生成路径、审核路径和下游约定路径的对应关系：在隔离环境或播出技术负责人执行的只读检查中验证素材可访问、身份一致。未能检查下游时明确兼容性结论的限制，不接入实际播出来凑证据。

检查报告注明输出版本与检查时间。演示一次人工修改后的重新核对，并记录最终审核版本；原自动检查报告不得被用于证明改后文件正确。v0.5 已将改后候选文件的独立复检及生产侧最终文件对比纳入本期；人工仍负责审核和上传，具体要求见产品需求第 12 节。

### 3.4 决定路径

- 直接生成通过支持范围内的语义与兼容性检查，则进入固定工具建设。
- 同时核实当前版本的 CSV／文本导入能力；直接生成不成立时，优先判断能否批量导入并保存 PLY，减少逐条操作。
- 需要 Computer Use 时，比较 Windows 原生与 Mac 经内网浏览器远程操作，检查授权、桌面会话及输入可靠性。
- 候选路径均不满足要求时，明确阻塞及需要的厂家／环境支持，不以模型猜测绕过。

调研依据、来源与限制见[PlayBox 与 Codex 操作路径调研](../research/04-PlayBox与Codex操作路径调研.md)。

### 3.5 大洋与 Playbox 导入导出能力验证（E17）

本轮将两套系统的能力验证明确纳入，分别按实际模块、版本与所管频道记录；不推定两个系统互通，不改变先交付 Playbox MVP 的顺序。E17 汇总双向能力，复用 E01、E02、E08 的已有证据，不重复测试。

| 检查项 | 两套系统分别做什么 | 完成依据 |
|---|---|---|
| 版本与入口 | 读取版本、导入／导出／另存为菜单与可选格式，区分节目单、报表和素材管理功能 | 版本与界面证据；菜单仅证明有入口 |
| 节目单导出 | 对已知内容的独立测试列表保存或导出支持的格式 | 保留原文件，核对条目、顺序、路径或素材编号、名称、准确时长、区段、时间安排和必要事件的保留情况 |
| 素材信息导出 | 检查能否导出路径／编号、准确完整时长、帧率及已有使用区段信息 | 样本字段清单与缺失项；不要求复制视频，不假定节目单报表包含素材全长 |
| 原样往返 | 将导出文件导入新的测试列表，保存、关闭、重开，再导出 | 对照原列表与最终列表，区分编号变化、显示变化和业务内容丢失；正确性不足不能算通过 |
| 生成文件接入 | 在原样往返基础上，用按已验证格式生成的最小测试文件验证接入 | 素材定位、顺序、时间和模式正确；随后再验证完整日单。大洋最低样例验证不等于完整适配交付 |
| 异常与限制 | 在测试副本验证缺素材、无法识别字段或不支持格式的提示 | 明确拒绝、警告或静默丢失的行为，不把“导入成功”提示当成内容正确 |

已有 Playbox PLY、大洋 Excel 和历史 XML 只能证明收到相应文件；具体导出操作及可导入性仍待现场证据。测试使用独立列表，不覆盖原件、不加载到正式播出任务。没有测试条件时记录“待测”，只凭文件分析不能关闭验证项。

产出按系统各一份能力记录：实际版本、测试文件、操作／界面证据、支持格式、字段保留、问题与下一步。Playbox 可行接入是其完整 MVP 的必要条件；大洋缺口独立记录，不成为 Playbox 的无关阻塞。原生打开／保存可作为可行路径，不强制要求两套系统都支持 Excel 或某种统一格式。

## 4. Computer Use 备选验证

先确认入选 Agent 及其操作组件在目标 Windows 环境中的可用能力、软件授权和完整操作链路，不以其他机器的演示推定目标环境可用。

验证内容包括：选择正确频道与编单、查找素材、插入与排序、时间／模式设置、保存到待审核目录、识别弹窗、拒绝误操作正式任务、主动停止和失败接管。模拟找不到素材、窗口变化和中途失败。

界面上显示完成后，仍须检查实际保存文件与预期编排。业务任务期间使用已验证版本及操作环境；不得依靠无上限重试维持运行。

## 5. 测试矩阵与样本管理

| 场景 | 检验重点 | 预期控制 |
|---|---|---|
| 正常完整节目单 | 行数、节目顺序、素材及输出 | 所有条目有归属，PLY 内容符合规则 |
| 完整节目包装 | 台标、下条预告、分级提示、导视与正片的对应及前后顺序 | 按频道确认规则保留和检查，不误当成任意填缝素材 |
| 重复播放 | 同一文件在多个位置出现 | 不去重、不漏条；复用可靠匹配，各次播放分别检查 |
| 连续日期编排 | 集数、重播、包装随日期的变化 | 用连续日单提取待确认规则，不自行认定递增集数或重复上限；不增加交付后自动改单 |
| 非零点起单与超出 24 小时 | 业务日、跨日、尾部内容及换日交接 | 展示实际安排；按确认的交接规则判断，不自动截尾，也不仅凭累计值判错 |
| 名称与准确时长不一致 | 文件名整数秒与时长列帧数等差异 | 使用确认的准确时长，不从名字截取时长代替计算 |
| 同名不同集／季 | 名称相似但内容不同 | 不能混集，无法确定时请人确认 |
| 同集多个版本 | FIX、BRC、时间及可用状态 | 按确认规则选择，不能仅依赖“最新”猜测 |
| 缺少素材 | 有节目安排但无文件 | 显式异常，不假装生成完整结果 |
| 精确时长和帧边界 | 秒以下差异、累计误差 | 采用确认的时间基准，不浮动累积误差 |
| 完整文件与有效使用区段 | 剪入／剪出、分段、同文件不同使用范围 | 按确认的有效时长编排，不自动裁剪正片 |
| 必要非视频事件 | 等待、停止、定时及试点必要事件 | 支持的事件正确保留；未支持时阻止交付，不静默忽略 |
| 宣传片填缝 | 多个合格组合或无解 | 合格组合均可；无解异常，不裁剪正片 |
| 可播期／固定时点 | 到期、定时、超时及跨日 | 检查约束，冲突交由人员裁定 |
| 无法读取／尚未写完的素材 | 网盘不通、部分文件不可读 | 报告不完整扫描，不静默漏掉 |
| 输入或素材任务中变化 | 扫描依据失效 | 不沿用失效检查结果交付 |
| 不支持的 Excel／PLY 结构 | 格式、编码、路径异常 | 明确不支持，保留证据 |
| 重试、取消、保存失败 | 输出覆盖、残留文件、接管 | 独立任务记录，失败结果不混入待审核交付 |
| 缺素材后显式继续 | 补齐后的读取、已确认项、受影响时间 | 重查本次依据，保留仍有效的选择，受影响项重新确认 |
| 退出返回、改选与更正 | 对话结束、选择撤回或更正 | 能恢复保存的进度；更正留痕并重检，不要求重新解释整份单子 |
| 提示与待解决问题 | 必需信息缺失、授权人员补充、仅供知悉项 | 未解决问题不能靠“忽略”通过；已满足规则的说明不强制重复确认 |
| 人工改后审核 | 自动报告对应版本、最终人工结果 | 人员辨别报告适用范围，重新核对受影响内容并记录最终版本 |
| 交接环境访问 | 生成、审核、下游约定路径与身份 | 按 E12 取得实际访问证据；本机能打开不足以放行 |
| 实际规模与繁忙时段 | 扫描、读取时长、任务量、进度显示 | 满足事前约定时限，不影响既有工作；单任务试算不代替负载验收 |

矩阵作为已采纳的验证覆盖要求，具体频道适用项和通过阈值在测试前确认。试点不含的字幕、直播等场景应明确识别为不支持，不能静默降级为普通录播条目。

本批首轮读取结果见[检查记录](../../data/production/2026-09-10_全天编单/首轮检查.md)：大洋 5 份在按每秒 25 帧、允许午夜回绕的计算口径下相邻时间衔接一致；Playbox 仅完成文件读取和时间数值累计，非零 #TC 等语义待客户端验证。这些结果不等于完整 E01／E04 通过。

本批已用于发现和方案调整，作为研究／回归样本；后续独立验收另收未参与调整的样本。

样本按用途分开：解释格式和调整规则的学习／调试样本、未参与方案调整的验收样本、人工构造的边界样本。验收样本一旦用于调整方案，应转为回归样本，并补充未参与调整的新样本。正常单、疑难单和不支持单分别报告；重复测试固定输入、规则、工具与模型配置，不仅展示最好的一次。

## 6. 人机比较与效率评价

### 6.1 比较前提

各方使用同一 Excel 版本、同一素材观察范围和已确认规则，并尽量控制编单复杂度、素材准备程度与审核范围。条件不同则单独标记，不能直接归因于 AI 或人员。

人工结果不是无条件正确答案。按节目身份、版本、顺序、使用区段、有效时长、必要事件、固定时点、可播约束、路径和填缝规则比较，由业务人员独立裁定差异。允许多个合格的宣传片组合，不以文件字节相同作为目标。

E11 用小实验比较现有人工做法、固定工具加人工处理歧义、同一套工具加模型处理歧义。逐环节记录收益与新增确认负担，明确模型具体减少的工作；不要求同时交付三套产品。正式双轨测试继续与既有人工流程比较。

### 6.2 每份任务记录【建议模板】

| 项目 | 记录内容 |
|---|---|
| 身份 | 样本编号、频道、播出日期、软件版本 |
| 输入 | Excel 版本、素材扫描范围和时间、规则版本 |
| 处理 | 模型与工具版本，扫描、匹配、编排、人工处理和审核起止时间，确认量及失败原因 |
| 差异 | 原条目、人工结果、AI 结果、差异类型、裁定依据 |
| 结果 | 实际运行来源状态、独立检查与人工审核绑定的文件身份、生产侧回读身份与时间、A→B／B→C 差异及已知原因；可投产与实际采用分开 |
| 任务去向 | 已完成、返工后完成、不支持、输入缺失、超时、取消、失败、人工接管；阶段状态与最终去向分开记录 |
| 问题处置 | 原因、修复、回归样例和关闭证据 |

所有正常运行任务都保留原产出、审核候选和生产侧取证文件、独立检查与修改原因；双轨测试和试运行同时记录完整投入。每个发起任务均有去向，不只统计成功结果。遇到影响业务正确性的错误，必须回到规则／工具修复及回归，不通过人工悄悄修正掩盖问题。

### 6.3 统一评价口径【已采纳，数值阈值待确认】

| 指标 | 记录口径 | 判定用途 |
|---|---|---|
| 每单人工总投入 | 输入整理、必要确认、查找／修改、最终审核及返工，按所有参与人员的人员分钟汇总 | 主效率指标，避免把负担转给审核或支持岗位 |
| 查找与编排投入 | 查找素材、选版本、排序、时间安排及填缝分别计时 | 判断首要目标在哪些环节改善 |
| 每单完成与等待时间 | 同一接单起点到人工审核完成，分记等素材、等模型和等人员时间 | 是否满足交单时限；被动等待不一律计成人工工作 |
| 有效完成比例 | 约定范围内所有发起任务中，最终达到业务审核要求的比例；同时标明有无实质性人工修改 | 避免用大量返工掩盖不足；质量合格与无需实质修改分开 |
| 人工修改与确认负担 | 换片、版本、顺序、时间、填缝与显示调整分开；记录问题数、处理时间及另找人解释次数 | 判断人员是否真正省事，不能以全量人工确认换取表面正确率 |
| 关键错误 | 错片错集、错版本、漏条目、必要事件缺失、不可访问路径和必需约束冲突逐项报告 | 关键错误不能被平均正确率稀释；有裁定、修复和关闭证据 |
| 覆盖与任务去向 | 范围内完成情况和全部来单覆盖分别报告；所有任务的未完成原因、取消与接管留档 | 展示日常工作真实覆盖，避免筛掉失败或不支持任务 |
| 持续维护投入 | 补规则、使用支持、版本更新和故障处理分别记时 | 与单次任务时间分别展示，判断扩大使用后的净收益 |
| 来源与实际采用 | 按批准版本记录指定／非指定／无法证明，原样采用、变更后采用、明确未采用、待确认；精确变化与业务变化分开 | 检验版本可信及实际效果，未知项不得从分母中消失 |

同类任务的人工节省比例为：（原流程人工总投入－辅助流程人工总投入）÷ 原流程人工总投入。原流程基线缺失或不可比时不报告节省比例。取得足够样本后同时报告典型情况和耗时较长的情况，不以最快一单代替整体效果。

探索阶段不设节省比例；试点测量前依据原流程基线确定目标降幅、最大完成时间和评价样本，推广前须满足人工总投入下降及约定质量条件。未满足时调整或暂停推广，按原标准重新验证；不能测试结束后为通过而降低标准。

## 7. 阶段放行条件【已采纳，具体阈值待联合确认】

| 阶段 | 放行前需要的证据 |
|---|---|
| 线上探索进入完整本地建设／采购定选 | 明确可行路径及支持范围；关键格式与规则有证据；对应路径的 E10 最小断网验证通过；线上 MVP 和模型能力／速度筛选通过，采购定选另须有目标硬件真实负载实测及完整报价；人工基线和 E11 初步对照说明工作收益；环境、授权及未知项有处理计划 |
| 建设进入双轨测试 | 固定工具与规则版本；E14 版本防改与独立来源记录、E15 独立检查与文件绑定可用；异常续编、确认记录、输出隔离及报告版本可用；代表性样例通过；验收样本与调试样本分开，评价标准在测试前确定 |
| 双轨进入小范围生产 | 约定样本与周期通过；关键差异有裁定和关闭证据；E07 完整离线、E12 交接环境访问与改后人工检查、E13 负载和恢复、E14 来源证明、E15 改后复检与放行、E16 生产取证和对比通过；人工审核、接管及退出方案明确 |
| 小范围进入推广 | 1—2 个频道试运行质量与时限达标；计入确认、审核、返工后的人工总投入下降并满足事前目标；维护负担可承受；新频道差异检查完成；业务、技术和项目共同批准 |

样本数量、连续运行天数、最大允许耗时、缺陷等级及退出阈值，不在无数据情况下编造。必须在各阶段测试开始前确认，不能测试结束后为通过而修改标准。

评价分开记录“关键问题未解决，不可交付”“自动检查通过，待人工审核”“人工最终审核通过”。运行来源、独立校验、人工审核和实际采用分别记录；v0.5 增加可投产、待生产回读及采用结果的追溯状态，仍不新增自动上传或播控功能。

生产试运行期间如不能生成可靠结果，回到既有人工编单流程。系统不负责撤回已人工上传的文件；生产侧处置仍按播出团队现有程序执行，试运行前须明确联络和交接责任。

## 8. 模型和硬件验证

样本研究时并行开展 E10，使用现有或借测条件验证断网冷启动、内网模型调用、固定工具、人员选择保存与恢复。按所需路径验证实际请求、工具调用及必要图片输入的兼容性，不能仅按接口名称打勾；需要 GUI 的候选还须验证相应操作组件。失败候选保留阻塞理由，先收敛少量组合，避免同时深度改造六个载体。

线上流程基线仍保存模型名称、版本和运行配置。固定评价样本、规则与工具后再比较需求更低的模型，区分模型判断错误与工具／规则错误，并说明相对固定工具加人工的增量收益。

比较业务正确性、歧义识别、确认负担、稳定性和耗时。确定合适模型后适配硬件，并用相同业务样例进行本地离线回归；同时测试重启、失败恢复及无互联网条件下的依赖可用性。

前期线上数据范围须逐批确认，允许使用必要的真实节目单与素材信息，不发送完整视频。若使用截图操作，预览画面、路径与桌面其他内容的范围随批次一起确认。模型替换、工具更新或规则变更均触发相关回归，不因接口相似省略验收。

### 8.1 模型与硬件验证的执行次序（2026-09-10 更新）

1. 线上较强候选先完成最小业务闭环，不等待最终设备采购。
2. 固定样本、流程、工具与规则，比较本地可部署候选，形成任务上的能力下限与速度要求；保留失败案例和未参与调试的验证样本。
3. 每单记录请求次数、输入／输出及可取得的推理 token、上下文、重试、首响应、生成阶段 token/s、工具时间、模型等待和完整任务时间。无相应观测值标未知；不同模型不单按 token/s 比高低。
4. 根据交单时限、人工确认时间和工具耗时确定模型时间预算，再在目标配置、实际精度和约定并发下验证。线上服务性能不能作为本地性能证明。
5. 借测／供应商测试并完成 E10，取得双机完整报价后审批采购；到货后部署本地 LLM、Agent 和完整业务能力。
6. 本地使用同一评价口径重新验证质量、速度、并发、单机接管和完整离线流程。量化、引擎与部署差异均可能影响结果，线上通过不自动沿用。

具体阶段产出与指标口径见[行动计划](08-项目行动计划.md)。E06 对应模型筛选，E10 对应采购前最小断网，E07 对应到货部署后的完整离线验收；E11 持续衡量人工收益。尚未取得实际 token 数据或候选硬件实测，本轮不填写数值阈值、不指定采购型号。

## 11. 版本可信、独立验收与生产对比【v0.5 新增】

| 编号 | 验证目标 | 通过证据 |
|---|---|---|
| E14 | 防止业务 Agent 修改批准 Skill／项目，或可靠识别非指定运行 | 业务身份无法写发布、批准清单、校验器、凭证和证据区；实际执行副本与批准内容可独立核验；无法证明时明确阻止标准放行 |
| E15 | 独立检验原产出和人工改后文件，放行绑定同一内容 | 检查器拒绝已知错误、未知关键字段和伪造报告；文件内容变更使旧通过记录及旧审核失效；符合条件的文件才给出可投产结论 |
| E16 | 确认生产采用和实际变更，为优化保留依据 | 有可信 C 文件来源、稳定快照及任务关联；正确区分 A→B 与 B→C、精确与业务差异；未知归属和缺取证不被判为已采用 |

验证只在批准的隔离环境、任务副本或约定只读取证范围执行，不在生产中故意制造错误。测试至少覆盖：

- 使用业务账号尝试修改 Skill、规则、脚本、依赖、批准清单、校验器和证据；不能只检查一份 SKILL.md 是否只读。
- 未提交修改仍沿用同一个版本号；任务中修改后恢复；从别的位置加载同名 Skill；旧任务在升级后恢复；双机切换至不同版本。应锁定原副本或准确标记非指定／混合／无法证明，不能因开始和结束指纹一致就判为指定版。
- 来源记录或凭证由 Agent 伪造、改写或缺失；实际使用非指定版本却填写批准标签。独立记录拒绝冒认，正常流程不放行。
- 指定版本生成错片、漏条目或时间冲突；内容正确但来源不明。分别展示来源和质量结果，任何一项异常不能被另一项通过抵消。
- 校验后的文件被替换、人工修改、同名覆盖；人工审核对应旧文件。必须对实际最终候选重检并重新绑定审核，不能用旧凭证上传新内容。
- A、B、C 完全一致；A→B 有人工更改且有原因；B→C 被另改；仅自动编号／编码／路径规范化改变；未知关键字段变化。分别判定精确与业务差异，不能把每个文件变化都归为人工纠错。
- C 缺失、只有未经核实的手工副本、同名不同任务、同频道日期多次提交、取证中仍在写入。保持待确认，独立保存各提交版本，不覆盖历史。
- 原样文件未经事前审核被放入测试生产接收目录：应记录实际出现与验收缺失，不能倒推其获批。目录存在不得冒称系统已加载或已播出。
- 已有部分记录时重试或故障恢复：不重复记采用，不丢原产出和回读证据；迟到的回执更新关联，不修改旧事件的事实。

现场若未提供可接入的入库控制，应明确“能够出具放行结论并识别绕过”，不能将其验收为“物理上禁止任何人绕过上传”。人工工作量统计包含最终复检、上传交接和说明修改原因的新增投入。经裁定的修改形成回归样本后，还需独立验收和维护发布，不能自动改运行中的 Skill。
