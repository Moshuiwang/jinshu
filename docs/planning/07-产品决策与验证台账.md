## 1. 当前决定

| 编号 | 当前决定 | 来源与边界 |
|---|---|---|
| D19 单一执行者与人员分工 | 每个执行任务只能由人、Agent 或程序中的一方执行，跨方流程须拆任务；人员沿用现有频道分工，不新增自动派工或接手审批 | 用户纠正模块分工表并明确要求重拆此前已确认内容；见[任务拆解](../product/03-编单动作与交接设计.md) |
| D20 EPG 接收与版本 | 普通复制到约定网盘；程序轮询识别内容变化，保存原样副本、源修改时间、大小、毫秒级首次抓取时间及 SHA-256 | Windows 映射文件夹是已知使用方式；实际网盘、接收完成判定、轮询周期及传媒目录／文件名／内容约定待调研 |
| D21 多版本独立编单与主键 | 同频道同日期不同 EPG 内容版本分别继续编单，输出以文件名或目录名标版本且不覆盖；任务、输入、节目条目入库并有独立主键 | 不等人工选出唯一输入版本，不因新版出现停止旧任务；固定输入不能被静默修改，工程主键沿用 UUID |
| D22 共享素材索引与变化影响 | 首次索引、后台增量更新、定期核对、每单绑定观察版本、交付前复核引用文件；已交付引用素材变化时保留结果并提示需复核 | 用户已认可，替代“每单全库重扫”和原不持续监测素材的边界；具体更新周期／接口和保护规则待调研，自动另生成新版尚未决定 |
| D23 Agent 主导匹配 | Agent 理解要求、形成检索条件、比较候选和作有依据的选择；程序分别检索、核对明确限制及入库；剩余业务歧义由人决定 | 已按唯一执行者拆开，程序检查完整不能独自证明语义判断必然正确 |
| D24 培训手册与拼接 | EPG 是节目主体，需依培训手册加入台标、广告、包装等；Agent 在明确规则和自由空间内形成方案，程序核对可计算条件 | 用户明确有大量自由发挥空间；允许多个合格方案，不以复刻人工唯一答案评分；实际手册条文待传媒提供或核对 |
| D25 模型评估路线 | 先 Codex＋OpenAI 业务基准，再 Qwen3.8-27B API、云端自部署，最后本地估算与拟购配置实测 | OpenAI 是基准，不作为本地候选；Qwen 是首个可部署候选。相同业务包验证质量与日批次时间，目前未运行 |
| D27 日批次目标 | 每天 20 多频道，争取 2 小时内完成；记录模型、工具、排队、人工等待与返工 | 待实测目标，准确频道数和测试条件在运行前固定；检查通过的测试交付不冒充现场验收 |
| D28 Mac 参考配置 | 用户偏好两台 Mac Studio Ultra，每台 128GB；故障后单机仍应承担约定负载 | 代际、GPU 核数及完整配置未定，非采购决定；云端 NVIDIA 速度不直接换算为 Mac 性能，采购前实测 |
| D29 生产权限与密钥 | 防 AI 越权及人员借 AI 误操作；最小权限，危险凭据不交 Agent 读取，受控程序限制实际动作 | 语言／指令处理、凭据隔离、开发与生产边界见[安全专题](../product/04-生产保护与权限密钥边界.md)；现在记录开发约束，详细机制后续落实 |
| D26 两层安全与时机 | 一是局域网独立运行、不联网；二是防止 AI 越过护栏造成不可逆生产破坏；详细方案在调研和基本方案确定后展开 | 安全目标保留，已有技术草案后续复核；不以完整安全实现阻塞云端能力评估，研究不扩大生产写入权限 |
| D17 工作人员主界面 | 确定使用 Codex，通过固定任务、Skill／Plugin 完成业务协作；大屏只读展示，人工审核仍在 Playbox | 用户本轮明确“确定下来用 codex 来做为工作人员的主要界面”；替代“Codex 仅为优先候选”，本轮不自建替代性业务客户端 |
| D18 流程完整性 | Skill 指导协作，程序约束必经步骤；任何必需步骤缺失、失败或无法确认，任务保持未完成，不产生正常交付 | 用户同意上一轮原则；固定输出和 Agent 自报不构成完成证据，具体控制机制、第三方依赖及真实效果待验证 |
| D02／D12 阶段 | 调研 → OpenAI 基准 → Qwen API → 云端自部署 → 本地估算及基本方案 → 安全与实现验证 → 采购交付 → 试运行 | 用户本轮调整，替代此前“线上 MVP 先行”；具体顺序见行动计划，完整 MVP 和安全控制不作为初次模型评估前提 |
| D06 首期范围 | Playbox 常规录播频道先做完整 MVP，大洋本轮独立验证导入导出，完整适配后续开展 | 两套系统分管不同频道，不跨系统配对样本；大洋待测不阻塞 Playbox |
| D09 原产出可信 | 保护批准版本，锦书自己的产出保留独立来源和内容检查 | 仍待实现验证；不由 Agent 自报一句成功就作为检查通过 |
| D11 交付边界 | 自动取得 EPG → 编单检查后交入 Output → 人员在原系统导入、查看修改并确认，按原流程执行 → 锦书事后只读取得最终执行文件并对比 | 用户讨论 F01 后明确；取消人工改后回锦书复检及投产放行。EPG＋原产出＋最终执行文件为核心历史，中间审核文件非必交 |
| D13 两个主指标 | 收到完整 EPG 到 Output 交付的系统耗时；原产出与最终执行单的业务一致／差异情况 | 用户调整 F06：暂停人工耗时、节省比例及 E11 人机效率对照，不再以人工总投入下降作本期验收前提；详细口径只见验证计划第 6 节 |
| D14 浏览器大屏 | 提供自动刷新的状态网页，可用浏览器在大屏上展示系统、任务、结果和事后对比状态 | 用户在 F05 中新增，纳入交付；只读状态展示不增加审核后台，虚构数据演示页面已形成；后续定为按播出日期切换、横向编号工作流与C双环六态，真实状态接入待验证 |
| D16 大屏内网独立运行 | 大屏源码作为唯一设计基线；从展示需要反推状态协同、数据库、模块接口和离线部署 | 用户明确要求归入仓库并形成产品及技术方案，见 [Issue #12](https://github.com/Moshuiwang/jinshu/issues/12)；当前文档设计不等于后台、安装包或现场已实现 |
| D07／D15 资料与记录 | 项目侧先读文件、提取字段和整理规则；只请人补无法判断的业务含义。大洋缩减到本轮接入验证所需资料 | 用户认可 F03、F04；不索取人工计时、联系人名单、原视频或逐项手填技术表 |
| F07／F08 简化 | 差异自动记录和归组，未知原因保持未知，真正需修复的事项再登记；各文档只维护自身职责 | 用户同意结合新边界处理 F07，并按完整审核完成修订；不把每条差异都变成错误或人工问题单 |

最终封闭内网、两台主机独立承担故障后负载、预算争取 10 万元／最高 20 万元、人工执行与不自动播控等既定约束继续适用。具体配置、时限和渠道未定，不因文档修订变成采购或上线批准。

## 4. 下一步与更新方式

Codex 主界面及已确认任务拆解作为业务基线。现在优先整理模型评测包：围绕业务理解、素材匹配、培训手册解释、拼接和工具使用形成用例，先固定 Codex＋OpenAI 基准条件和整批记录，再准备 Qwen API、自部署与 Mac 比较。无需先拆完并实现全部后续模块；具体任务及唯一执行者见[模型评估专题](09-模型评估与本地选型.md)。第三方框架是否采用仍是研究建议，不自动安装或接入。

先按资料清单补一份 Playbox 配套实例，核对两套系统现有版本与测试条件。项目侧先提取已有信息并整理草稿，再集中反馈缺口；不要求现阶段提供责任人名单、完整规则手册或人工计时。

实验完成后只补结论、依据位置、剩余问题和下一步。失败或没有条件时如实记待验证；未取得的实际采用、正确率或耗时不得填成成功。

状态协同的需求与设计保留为后续实现依据，当前不先推进后台建设。具体现场信号未明确前，不把人工完成和 Playbox 接收当作已具备接口；统一按更新后的行动计划推进。
