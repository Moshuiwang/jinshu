# 项目行动计划

版本：v0.10｜2026-09-10｜先建立 Codex＋OpenAI 基准，再评估 Qwen 与本地配置

本页只维护推进顺序。实验方法与计时见[模型评估与本地选型](09-模型评估与本地选型.md)，安全目标见[生产保护与权限密钥边界](../product/04-生产保护与权限密钥边界.md)，传媒配合统一见[资料清单](03-传媒资料准备清单.md)，结果见[台账](07-产品决策与验证台账.md)。

## 当前第一项

先准备固定业务样例和最小测试工具，用 **Codex＋OpenAI 模型**跑代表频道，再跑完整一天的频道组合，记录合格结果及模型、工具、排队、人工等待、重试耗时。评估每天 **20 多个频道、争取 2 小时内完成**的目标。OpenAI 是能力与流程基准，结果仍需检查，不预先当作必然正确；目前没有实际模型或整批运行记录。

完整 EPG、素材信息与培训手册先由项目侧核对和提炼；缺失的业务含义集中请传媒补充。现有 Playbox 3 份 PLY、大洋 5 份 Excel 不等于配套评测包。构造样例可验证方法，但不能当作真实业务能力通过。

## 模型到本地配置的四步

| 顺序 | 工作 | 得到什么再向后推进 |
|---|---|---|
| A Codex＋OpenAI 基准 | 用固定业务任务验证工作方式，拆开单频道与整批计时 | 合格率、完整批次耗时、调用与返工记录；明确瓶颈在模型、工具还是等待 |
| B Qwen 云端 API | 首个可本地部署候选 Qwen3.8-27B 跑相同任务 | 能力是否够用、与基准的差异；准确服务身份与限制，不把托管增强版当原权重 |
| C 云端自部署 | 在获准租用资源上运行目标权重与配置 | 可复现的质量、首字、token/s、批量时间与资源记录；没有具体费用和资源条件不启动 |
| D 本地估算与验证 | 依据 C 形成候选方案，优先考察用户偏好的 Mac Studio Ultra 128GB 两台 | 先说明估算依据与未知项；拟购配置实测、报价和必要验证结果齐备后才决定采购。NVIDIA 云端速度不能直接按比例换算成 Mac 性能 |

具体样本、次数和成功条件在运行前固定。先确认模型能力，再为自部署租机投入费用；本次只整理方案，不启动实验或采购。D 先形成基本方案；拟购配置实测、报价和必要验证结果须在采购决定前齐备。采购后再完成完整离线、恢复和展示验收。

## 后续阶段

1. 基本方案更明确后，细化本地组件与两层安全：局域网独立运行，以及防 AI／人员借 AI 误操作破坏生产。权限和危险密钥约束从开发起遵守，详细设施与安装部署不在当前展开。
2. 按明确范围实现并用目标硬件验证，补齐本地模型质量、日批次速度、故障后单机承载、E10 最小断网及适用安全证据；拟购配置测试与完整报价齐备后才进入采购决定。
3. 批准采购后完成本地交付、完整离线、恢复、原系统交接和安全验收；不要求采购前建成所有恢复与大屏能力。
4. 先在约定 Playbox 频道试运行，积累实际采用与差异，再推广。完整大洋适配仍为后续范围，必要格式探索可并行。

## 硬件参考与当前投入边界

用户偏好 **两台 Mac Studio Ultra，每台 128GB**；代际、GPU 核数及完整配置尚未确认，仅为参考，不保证此配置达标。两台模型主机争取合计 10 万元、最高 20 万元，故障后单机承担约定负载的既有要求保留。先验证单机，再评估双机；不是把两台内存合起来估算一台模型容量。

安装及部署目前只调研兼容性、租测条件、离线依赖和重大风险，不提前制作完整安装包、配置真实服务或展开运维实施。权限与密钥管理现在记录要求，具体技术选择之后确定。

模型评估看业务能力、首字、token/s 和任务／整批时长；最终产品继续记录收到 EPG 到 Output 的系统耗时及原产出与最终执行单的业务一致／差异。保留人工等待用于诊断，不恢复人工工时或节省比例调查。各阶段完成情况只更新台账，不把文档通过算成模型、硬件或安全通过。
