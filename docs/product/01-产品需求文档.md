# 锦书 · 智能编单系统产品需求文档

版本：v0.7｜2026-09-10｜纳入真实日单发现与两套系统的频道边界；现场规则及实现待验证

## 1. 产品定位与目标【已确认】

2026-09-10 产品负责人确定项目名称为“锦书”，拼音及英文标识为 `jinshu`；完整名称为“锦书 · 智能编单系统”。

本产品帮助常规录播频道的编单人员提高效率，减少查找素材和手工编排，并把人工确认、审核和返工计入实际工作量。以对话式 Agent 为操作入口和执行载体，Codex 为优先候选而非固定选型，交付编单技能、配套工具、业务规则及配置。安装包形式不影响当前产品定义。

人员提交编导生成的 Excel 初版节目单后，系统读取当前素材库信息，匹配和编排后生成待审核 PLY。每份产出标明实际运行版本的可信状态，经独立校验和人工审核后，由人员上传；随后取得生产侧最终文件，与原产出及人工审核文件对比，形成可追溯的采用与修改记录。本产品仍不承担正式上传或实际播出控制。

前期目标是证明真实节目单能够正确完成编单并通过人工审核，暂不设节省比例。全过程记录人工投入、系统等待、确认量和返工；推广前必须证明把确认、审核和返工全部算入后，人工总投入确实下降，且质量、交单时限、离线和恢复要求均达标。具体降幅在取得原流程基线后、相应测试开始前确认。

2026-09-10 执行顺序明确为：线上模型验证 MVP → 筛选本项目模型能力与速度下限 → 目标硬件实测、预算及采购 → 本地 LLM 与完整业务部署 → 完整离线验收与试运行。速度须同时满足人员等待和整单交单要求，线上性能不能直接作为本地性能证明，详见[行动计划](../planning/08-项目行动计划.md)。

产品价值以实际减少的工作衡量。前期通过小实验比较现有人工做法、固定工具加人工处理歧义、同一套工具加模型处理歧义，明确 AI 在哪些环节带来额外收益。无需建设三套产品。验证、工程建设、双轨测试、小范围试运行、推广分别放行；评价口径见[验证计划](../planning/02-前期探索与验证计划.md)。

## 2. 范围【已确认】

2026-09-10 产品负责人确认：**大洋与 Playbox 是两套系统，分别管理不同频道。**本批大洋 Excel 与 Playbox PLY 分别属于各自系统的频道日单，不是同一任务的输入与输出，也不代表系统间转换流程。沿用本期 Playbox／PLY 优先、大洋后续独立适配的范围。

### 2.1 本期包含

- 单次任务接收一份 Excel 初版节目单，识别并确认频道、播出日期和编排内容。
- 启动后读取当前网盘素材信息，建立本次任务的素材信息快照。
- 按频道人员确认的规则匹配节目、集数、版本及相关素材，完整编排所需台标、下条预告、分级提示、节目导视和宣传片；具体使用条件与顺序由频道确认。
- 区分文件完整时长与节目单的有效播出时长，按确认的使用区段、必要事件及规则完成时间编排、宣传片填缝和检查。
- 集中处理无法确定的匹配、缺失和时间冲突。
- 生成并校验 PLY，交付独立待审核位置及检查报告。
- 保留本次任务的输入、规则版本、人工确认、校验结果和输出记录。
- 保护指定 Skill、项目程序、规则与校验组件；每份产出具有独立可核验的运行版本记录，区分指定版本、非指定版本和来源无法证明。
- 对系统产出及人工改后文件执行独立校验；通过校验与人工审核后才给出可投产结论。
- 取得生产侧最终文件，与系统原产出及审核后文件进行内容对比，记录直接采用、改后采用及未确认采用等情况，为版本优化提供依据。

### 2.2 本期不包含

- 人工审核后的正式目录上传、生产发布、素材迁移、播控和实际播出。
- 交付后的素材变化监测、新旧 Excel 差异比较、素材持续扫描和自动补改；新增的生产文件回读与对比按第 12 节执行。
- 飞书自动获取或自动跨网同步；Excel 由人员通过 U 盘按公司批准方式带入。
- 外挂字幕制作、转换和关联；第一试点选择不需外挂字幕的常规录播频道。
- 体育直播临场调整、视频内容质检、合规审查和独立版权授权审核。
- 大洋完整编单适配实现。本期详细定义 Playbox／PLY；大洋的导入导出能力验证纳入前期探索，完整适配仍作为后续方向。

版权授权由上游负责；本产品必须检查已提供的可播日期、素材版本、时长和编排约束。缺少频道规则规定的必需信息时列为待解决问题，补齐并重检前不可交付；不能凭空推断授权，也不能只靠“忽略”通过。

产品负责人已确认：常规录播覆盖首期主要工作，上述排除项不妨碍启动试点。具体频道、岗位和样本后续补充。

## 3. 人员与责任

| 角色 | 职责 |
|---|---|
| 编单人员 | 提交 Excel、确认必要信息、处理歧义、领取文件 |
| 人工审核人员 | 在 Playbox 中审核，修改后提交最终候选文件复检，确认校验对应同一文件后自行上传；说明修改原因，配合取得生产侧最终文件；可否与编单人员同人为业务待确认事项 |
| 频道业务人员 | 提供当前工作流程、实际规则和样例，裁定业务歧义及人机结果差异 |
| 播出技术负责人 | 确认目标软件版本、目录边界、测试条件、审核与下游约定环境的素材访问及生产交接条件 |
| 维护负责人／支持人员 | 处理运行故障、版本更新和规则维护，提供用户可用的接管指引；具体人员待指定 |
| 项目负责人 | 组织需求和探索，联合业务与播出技术负责人决定阶段放行 |
| 工程负责人 | 组织固定工具、格式与路径验证，记录版本、实验、失败和修复证据；具体人员待指定 |
| 版本发布与验收维护人员 | 管理批准版本及独立校验规则、发布和回滚；业务 Agent 无权修改其发布依据、校验记录与凭证；具体人员待指定 |

以上角色说明业务分工，不要求在研究或线上 MVP 阶段提供姓名或联系人名单。当前只请求具体资料、规则解释和验证反馈；试运行与交付前再落实实际审核、维护和接管安排，记录到[决策与验证台账](../planning/07-产品决策与验证台账.md)。技能不得将对话中的“已生成”表述等同于人工审核通过或生产发布。

## 4. 人员工作流程【已确认】

1. 人员在选定 Agent 的编单任务中选取 Excel，发起编单。
2. 系统展示识别出的频道、绝对播出日期、节目及必要事件数量、输入问题。必要信息由人员确认；相对日期与 Excel 不一致时先澄清。
3. 系统扫描指定素材范围，读取名称、位置、时长及可取得的版本信息。
4. 根据规则匹配、编排及填缝，完成可确定的部分；集中列出异常。
5. 人员处理异常，系统重新检查受影响的编排。缺失未补齐、歧义未解决时不标记为可交付。
6. 保存不可被业务 Agent 覆盖的原始产出，独立验收组件检查运行来源和文件内容，展示版本状态、校验结果及文件身份；正常产出进入待人工审核。
7. 人员在 Playbox 中审核并按需修改；改后候选文件重新提交独立校验。审核确认与校验结论均绑定同一文件，满足条件后提示可投产，由人员上传。
8. 在约定交接完成点回读生产侧实际文件，核对频道、日期和任务归属，对比原产出、审核后文件与生产文件，展示采用情况和差异；未取得可靠生产证据时保持待回读。

人员面对业务说明和必要选项，无需编写复杂提示词、执行命令或理解文件格式。提交新文件或显式发起新的编单，均建立新任务；同一输入的未完成任务可以显式继续，见 4.3。本期不实现持续更新服务。

### 4.1 典型交互示例【建议基线】

> 人员：按这个 Excel 生成 2026 年 9 月 10 日的编单。
>
> 助手：识别到频道 A、播出日期 2026 年 9 月 10 日，请确认。日期以节目单的业务时区为准。
>
> 助手：第 12 集找到两个候选版本，分别为……，对应时长为……，请确认使用哪个。
>
> 助手：这份 PLY 的运行来源已核验、独立检查通过，待人工审核。修改后请提交复检；校验与人工审核都通过后再上传，随后回读生产文件确认采用情况。

示例不承诺任一候选 Agent 已具备全部界面控件。确认方式须验证可持续呈现、可恢复，并将人员选择保存为任务记录。

### 4.2 集中处理异常【已采纳】

每条异常显示原 Excel 行、节目与集数、候选素材及版本／有效时长差异、推荐依据、需要人员做什么，以及对时间编排的影响。人员可以改选、撤回尚未提交的选择；已提交的选择如需更正，保存更正记录并重新检查受影响结果。

- **待解决，不可交付**：缺必需素材或信息、版本歧义、时间冲突、未支持格式或必要事件等。说明补充方式和业务裁定角色，解决并重检后才可继续交付。
- **仅供知悉**：已符合规则的信息说明，不要求人员重复批准，也不得混入未解决问题。

同类原因可以分组呈现，不默认批量接受全部候选。由谁补充事实、所需依据及如何留痕写入频道规则；对话中的临时指令不能替代已确认规则。等待时显示已完成范围、未解决项和下一步，人员无需持续守着对话。

### 4.3 等待补料与继续任务【已采纳】

| 情况 | 人员体验与处理 |
|---|---|
| 同一 Excel 缺素材 | 保存已完成内容，显示待补料；人员补齐后显式继续，重读相关素材、检查本次依据有效性并重算受影响编排 |
| 人员退出后返回未完成任务 | 恢复任务进度和已保存选择，显示待处理问题；不要求重新描述整份单子 |
| 已确认素材或条件改变 | 保留仍然有效的确认，受影响的选择重新确认；不能沿用旧校验结论 |
| Excel 换版或人员另发起编单 | 新建独立任务，不实现新旧 Excel 自动比较，也不静默继承旧版决定 |
| 已交付后素材或节目安排变化 | 仍由现有人工流程处理，不自动补改；人工最终文件纳入复检及生产回读对比，变化原因独立记录 |
| 人员取消 | 停止自动操作，说明已完成与未完成范围，历史记录及已交付结果不被静默覆盖 |

## 5. 输入输出约定

资料提交统一按[资料与验证交接清单](../planning/03-传媒资料准备清单.md)执行。下文为需求／验证覆盖，不作为另一套逐项索取清单；已收信息先自行提取，剩余缺口合并反馈。

### 5.1 Excel

已确认其为编导提供的初版／简要节目单，名称和时长不保证与实际文件一一对应。系统须保留原文件及行位置，任何匹配、调整和异常都能回指原始条目。

2026-09-10 已收到的大洋 Excel 是其所管频道的日单资料，包含播出时间、节目名、时长三列；是否属于业务编单前的输入仍待确认，不能用它替代 Playbox 对应的编导初版表。

待样本确认：表头、工作表、合并单元格、隐藏行、日期格式、跨日表示、公式值、频道与时区字段，以及能否一份文件包含多天或多频道。本期遇到未支持格式应明确报错，不静默漏行。

完整 MVP 的素材信息必须支持准确完整时长、实际帧率及每次使用的区段／有效时长核对；计划开始时间、固定时点与换日属于编排信息。姓名、文件修改时间或文件名中的秒数均不能替代这些事实。资料字段与缺项处理统一见资料清单第 3 节，不复制或上传原始视频。

### 5.2 网盘素材信息

视频文件位于封闭局域网的网盘。系统只读扫描指定范围，取得编单需要的信息；本期不修改、删除或重命名原素材。

素材信息快照记录扫描时间、来源范围、文件身份信息及读取结果。快照是本次观察记录，不代表复制或冻结视频文件本体。读取失败、文件仍在写入、身份或时长无法可靠确定时，应列为异常。

扫描范围和并发按现场规模验证；分别记录扫描、取得时长所需时间及对现有工作的影响。使用缓存时须在本次任务中确认有效性，不用旧缓存代替当前信息。界面应说明扫描进度、不可读取范围与待处理原因。

### 5.3 PLY 与附带记录

- 主输出：目标 Playbox 版本能够正确读取的 PLY，存入待审核位置。
- 检查报告：输入来源、素材扫描时间、条目对应、使用区段与有效时长、必要事件、时间检查、填缝内容、异常处理、对应输出版本和检查时间。报告明确只适用于该输出与本次观察到的素材状态。
- 任务记录：本次规则和工具版本、模型配置、人员确认和最终校验结论。
- 产出来源与采用记录：批准版本及实际执行内容的证据、原产出与最终候选文件的身份、独立校验记录、人工审核确认、生产侧回读文件及差异报告，详见第 12 节。

PLY 内实际保存哪些字段、使用何种编码及路径规则，须以样本和兼容性验证确定。不能把推测字段写成既定格式。

生成端路径、人工审核端路径与下游约定路径须建立明确对应。试运行前，在隔离测试环境或由播出技术负责人执行的只读检查中，验证相同 PLY 的素材可访问且身份一致。生成电脑可读或客户端能打开文件不能单独证明交接环境可用。

## 6. 编单规则

| 规则 | 要求与状态 |
|---|---|
| 素材匹配 | 按频道人员确认的命名和对应规则执行；不确定时列候选、解释差异，由人员确认【已确认】 |
| 版本选择 | FIX、BRC、上传时间等是会议中的现状线索；具体优先级、例外和可用状态须写入频道规则并确认 |
| 时长与时间 | 分别记录文件完整时长及已确认使用区段的有效播出时长；无区段信息时须先确认是否整段使用，不能默认二者相等；帧率、取整、剪入／剪出点及分段边界由样本验证 |
| 必要事件 | 由试点确认等待、停止、定时及其他非视频事件是否存在；使用的事件必须被正确表达和校验，未支持时明确阻止交付，不静默忽略 |
| 填缝 | 只使用指定且在有效期内的宣传片，遵守频道规则；不能填齐时异常，不自行裁剪正片【已确认】 |
| 定时与跨日 | 按频道确认播出日、时区、起止点与换日交接规则；审核显示跨日部分及超出目标时段的内容。真实样本有非零点起单、条目累计超过 24 小时的情况，不能据此自动截尾或判错；尾部是否超编及如何处理待现场确认 |
| 节目包装 | 按频道规则检查台标、下条预告、分级提示、节目导视等与正片的对应关系及顺序，不能把它们一律当作可替换的填缝片；具体插入条件、次数和例外待确认 |
| 重复播放 | 同一素材允许按规则出现在多个位置，不按文件名去重；已确定的匹配可复用，各次播放的顺序、使用时长及可播约束分别检查，减少无意义的重复确认 |
| 版权与可播期 | 上游负责授权；检查提供的可播日期等约束，缺少频道规则规定的必需信息时列为待解决，补齐重检前不可交付【已确认／审核细化】 |
| 覆盖不足 | 先完成能确定的部分，问题集中处理；无规则支撑的决定不能静默通过【已确认】 |

名称中的时长仅作为匹配线索；时间编排以经确认的准确时长与使用区段为准，保留帧精度。连续日期的集数、重播和包装差异可用于研究频道规则，不从样本自行推导每天递增或固定重复次数。

本轮样本与检查依据见[真实日单首轮检查](../../data/production/2026-09-10_全天编单/首轮检查.md)。上述要求不代表已验证具体频道规则或客户端兼容性。

填缝可能存在多个合格组合，评判依据是业务规则与编排效果，不要求与人工逐字节一致。

上述时间及事件要求用于准确表达既定编排，不增加自动裁剪正片或视频编辑功能。第一频道如不使用某类事件或区段，应明确支持边界并保留不支持时的识别检查。

整段使用的条件可以由已确认的频道规则统一指定；符合条件的条目无需逐条询问。规则不足以确定使用范围时才集中请人确认。

## 7. 工程控制要求

以下为需求方向已确认、具体实现和验收阈值待设计的工程基线。

### 7.1 生成、检查与反馈

模型重点用于固定规则未直接解决的理解和匹配建议；精确计算、文件生成及明确规则检查由经过测试、固定版本的工具执行。规则已可靠确定的条目无需逐条请模型解释或请人重复确认。技能调用稳定工具，不在每次业务任务中临时修改程序或放宽规则。

检查须覆盖输入条目是否完整、素材对应、版本、使用区段、有效时长、必要事件、路径、播出模式和时间安排。生成后回读 PLY，并与预期编单核对。开发和验收阶段须通过目标 Playbox 实际读取验证；试运行前完成 5.3 所述交接环境检查。业务运行时哪些检查自动执行、哪些由人工在 Playbox 完成，须在探索后明确。

### 7.2 状态与异常

业务状态至少涵盖：待确认输入、扫描中、编排中、待处理异常／待补料、生成校验中、正在恢复、待人工审核、失败／已取消。具体显示形式由载体体验验证确定；状态由用户输入和工具结果共同决定，不能只凭模型文字宣称成功。

失败时停止后续写入，保留已完成的匹配、编排及原因，说明已完成和未完成范围。直接生成路径不得把未完成文件混入正式交付位置；Computer Use 路径应停止自动操作并标明客户端进度，支持人工接管。人员可显式取消任务。

任务中途如发现输入或已引用素材发生变化，应阻止以旧检查结果交付并提示重新检查。这是本次生成一致性要求，不扩展为交付后素材持续监控；生产文件回读与对比按第 12 节执行。

### 7.3 可追溯与变更

每个任务具有独立标识和输出位置，保留输入、扫描记录、规则、模型／工具版本及人工选择。同样的已确认编排数据，在固定生成器版本下应能复现对应输出内容。模型重新推断不保证逐次相同，因此须保存最终匹配决定。

人员在 Playbox 中编辑的每次鼠标操作不要求逐一跟踪；最终候选文件的复检、生产侧文件回读及与原产出的差异记录已纳入本期。原自动检查不能证明改后文件正确。各版本原文件、确认、差异原因和采用证据须保留，不被重试静默覆盖；记录保留时长、权限及清理方式待确认。

### 7.4 权限边界

素材区域只读，业务 Agent 仅能写任务工作区。发布版本、独立校验组件、批准清单和正式证据区由独立权限保护。生产侧回读采用限定目录的只读权限；业务技能不承担正式上传或播控。权限由运行环境约束，不只依赖提示词。具体保护与来源证明见第 12 节。

## 8. 实现路径：已确认主线与新增调研候选

| 路径 | 方式 | 决策依据 |
|---|---|---|
| 优先直接生成 | 解读 PLY，技能调用固定工具生成并校验 | 结构和业务语义可可靠掌握，目标 Playbox 读取及内容验证通过 |
| 其次验证批量导入 | 生成目标版本支持的 CSV／文本，经 ListBox 导入并保存 PLY | 早期核对菜单与授权；字段、有效时长、事件、路径和导入错误处理经过验证 |
| 必要时 Computer Use | 选定 Agent 通过已验证的电脑操作工具操作 Windows 上的 Playbox，插入素材、调整并保存 PLY | 直接生成与批量导入未满足要求，且目标环境操作能力得到实证验证 |

路径由工程探索决定并版本化，不让 Agent 在业务任务中随意切换。需要客户端的路径可能使用专用 Windows 编单电脑，其软件授权、操作隔离和接管条件待验证。三条候选路径最终均交付待审核 PLY，当前没有任何一条通过现场验收。

2026-09-08 调研补充：官方资料显示部分 ListBox Neo 版本支持 CSV／文本批量导入，可作为直接生成与逐条界面操作之间的候选方式。Computer Use 也可探索 Windows 原生操作与 Mac 经内网浏览器远程桌面操作两种部署方式。以上均未在目标设备验证，不改变本期输入输出或生产边界，详见[调研记录](../research/04-PlayBox与Codex操作路径调研.md)。

## 9. 模型与部署【已确认】

在研究样本的同时，先对少量候选组合做最小断网验证：重启入口、连接内网模型、调用固定本地工具、显示并保存人员选择，恢复后仍能读取；需要图形操作的候选追加相应验证。使用现有或借测条件，不以先采购最终硬件为前提。线上 MVP 可以先开展；采购定选及完整本地版本建设前至少有一条对应交付路径的组合通过最小断网验证。采购后再做完整离线验收，不将其提前作为线上 MVP 的前置。

线上模型仍用于验证完整业务流程；流程和评价标准稳定后，再比较需求较低的模型，按同一质量与人工投入要求适配硬件并完成全流程离线验收。最小断网验证不能替代最终离线验收。具体线上模型名称、版本待确认，不将语音转写中的名称作为选型结论。

最终运行环境为不能连接互联网的封闭局域网，本地模型供选定 Agent 调用。候选包括 Codex、WorkBuddy、OpenCode、Pi、DeepSeek Harness 和千问办公 QwenWork，具体身份、适配和限制见[载体调研](../research/05-Agent载体候选调研.md)。最终选择依据完整任务可靠性、本地模型与离线能力；没有候选通过时，报告阻塞，不降低工程要求。Mac Studio 仅为候选，不是已批准采购要求。

前期允许使用验证所需的真实节目单、素材名称和时长及必要 PLY 内容，具体资料与线上服务范围须事先确认；不发送完整视频。选择截图操作时，把预览画面、路径和桌面其他信息可能进入截图的范围一并说明并确认，未确认内容不进入线上输入。

### 9.1 新增硬件与热备要求【已确认】

两台模型主机合计争取人民币 100,000 元以内，最高 200,000 元，包含双机热备所需的独立运行能力；本轮不为配套设备与费用预留单列额度，网络与恢复要求仍保留。两台预加载模型，主机故障后自动切换，允许短暂停顿和未完成步骤重试，保留已确认进度、不重复交付。内部域名、固定 IP 等可由公司配置。模型热备不等于 Windows 客户端、加密狗、存储和整条生产链均有冗余；完整范围与报价见[本地部署调研](../research/06-本地模型硬件与双机热备调研.md)。

故障时向人员展示“正在恢复”、保留的确认与已交付文件位置。超过约定等待时间，提示如何交回人工以及联系谁；人员无需判断服务器状态。最大等待、接管时机和维护责任在试运行前按交单截止时间与人工补救时间确定，具体值待现场补充。

## 10. 阶段与验收

顺序为：前期探索 → 工程建设 → 人机双轨测试 → 1—2 个选定频道试运行 → 逐步推广到目标 Playbox 频道。第一探索／测试样本来自一个常规无外挂字幕频道。

各阶段须有证据和明确放行结论，不能仅按运行天数自动升级。业务负责人确认编单质量，播出技术负责人确认生产接入与接管条件，项目负责人共同决定是否放行。具体数量、时长、性能目标和容错边界，在样本与业务规则确认后制定，见验证计划。

验收使用未参与调规则的样本，由业务人员独立裁定关键差异；所有发起任务的完成、返工、不支持、失败、取消和人工接管均纳入统计。进入试运行前须验证第 12 节的版本来源、独立验收和生产文件对比链路；推广同时分析真实采用情况和修改原因，且人工总投入下降。不满足时先调整或暂停推广，再按原标准复验。

## 12. 运行版本可信与生产采用追溯【新增需求已确认，实现基线待验证】

### 12.1 每份产出都能回答三个问题

1. 是按指定版本运行的吗？依据是什么？
2. 这份具体文件是否通过独立校验与人工审核，能否按正常流程进入生产？
3. 生产中实际取得的是哪份文件，相对系统原产出和审核后文件分别改了什么？

这三个结论独立呈现。指定版本也可能生成错误文件；校验通过不等于实际已经采用；已经出现在生产中的文件也不能反向证明其来源合规或事前验收通过。

### 12.2 优先防改，同时提供可信来源记录

设计优先采用受保护的发布副本：业务运行账号只读 Skill、项目程序、工具、规则、依赖和运行配置；草稿与工作文件放在独立可写区域。发布、升级和回滚由维护权限执行，单个任务固定使用一份已批准版本；工作期间升级不让同一任务悄然混用新旧版本。

每个发布版本有完整内容清单和内容指纹，覆盖影响运行的 Skill／提示与配置、程序和工具、业务规则、必要依赖、Agent 与模型配置；本地模型权重记录相应内容身份。保留实际输入、人员选择和工具执行事件。版本名称和 Git 提交号只作索引，不能替代实际执行内容证明；同版本模型也不保证每次推断相同。

实际加载／执行的副本和产出身份由业务 Agent 无权改写的执行或记录组件绑定并存档。仅在开始和结束各算一次指纹，不能排除“中途修改、使用后恢复原样”；必须用任务固定的不可变副本，或能覆盖实际执行步骤的独立取证机制。校验组件、批准清单、证据存储及签名／凭证材料不得由被校验 Agent 自己控制。单纯把一个版本号写进日志，不构成可信证明。

如果暂时无法阻止 Agent 修改开发目录，允许保留修改用于调查，但产出必须按实际证据标记：

| 来源状态 | 判断依据 | 正常流程处理 |
|---|---|---|
| 指定版本，来源已核验 | 实际执行副本与批准内容一致，证据完整，产出绑定对应运行 | 继续独立内容校验和人工审核 |
| 非指定版本 | 已证明使用了未经批准或已变更的内容；记录实际指纹、变更项与阶段 | 隔离并交维护人员处理，不给标准可投产结论 |
| 无法证明／混合版本 | 缺证据、执行期间内容不可确定，或步骤混用了不同版本 | 明确标记，不猜测“应该是指定版”；按正常流程阻止投产 |

非指定版本的结果即使内容检查通过，也不得伪装为标准版本产出。正常处理是以批准版本重新生成并复验；若以后允许例外投产，需要另外定义有权批准者及绑定该文件的例外记录，当前不设置自动例外。变更发生在某份产出之后，不追溯篡改此前已取得可靠来源证据的产出状态。

### 12.3 独立验收绑定具体文件

生成器可做自检，但正式结论由独立、受保护的验收组件提供。该组件依据原输入、已确认编排、素材观察记录及批准规则，重新读取文件，检查完整性、片目／版本、顺序、有效时长、必要事件、时间冲突、可播约束与约定环境路径；未知格式和未知关键事件不能静默放行。目标软件兼容性和人工业务审核仍保留。

每次检查记录文件内容指纹、任务／频道／日期、检查器和规则版本、检查时间、检查范围、问题及结论。结果修改、复制成同名不同内容、恢复任务或重跑后，都不能沿用旧文件的通过凭证。人工审核确认同样绑定具体文件；提交前检查通过与审核通过的必须是同一内容。

正常可投产条件为：指定来源已核验、该文件独立检查通过、该文件人工审核通过、必要交接条件已满足。任一缺失时显示具体原因；修复后重检，不以 Agent 的口头“已完成”代替。

产品自身给出的是文件级放行结论，不负责上传。若要求技术上阻止人员绕过流程上传，须将凭证核对接入现场已有入库环节并落实权限；未接入前不能承诺物理上杜绝绕过。发现绕过或事后才取得的生产文件，如实记录实际采用与验收缺失，不能把已入生产补记成事前已批准，也不自动删除生产文件。

### 12.4 三份文件与生产侧证据

按任务、频道、播出日期和产出版本建立关联，至少保留：A 系统原始产出、B 人工审核与独立复检后的最终候选文件、C 在生产侧实际取得的文件。A 不可被业务 Agent 覆盖，B 每次修改新建版本，C 每次正式提交／替换均保留取证时间和快照。文件名、路径或修改时间相同不能证明内容相同；不同任务也不能只凭同名强行关联。

优先在指定交接完成点，由独立只读组件从约定生产目录回读稳定文件；记录来源位置、读取时间和内容身份，排除尚在写入或读取中发生变化的文件。若现场只能人工提供生产侧导出副本，须有可核验的生产侧回执或采集记录；普通手工拷贝只列为“声称来自生产的副本，来源待核实”，不能直接判定已采用。具体方式随现场条件落实。

生产目录存在、实际导入／加载成功和已经播出是不同状态。当前追溯至少证明约定生产接收位置的文件内容；没有系统加载或播出证据时，不声称已经加载或播出。未回读到文件也不等于明确未采用。

### 12.5 对比结果与优化记录

同时进行文件级精确对比和业务内容对比：前者回答是否原样采用，后者回答节目、素材版本、顺序、使用区段、时长、填缝、事件等是否改变。编码、自动编号或路径规范化等变化单独记录；只有在目标格式验证其不影响业务后才能归为非业务变化，未知字段变化不得忽略。

| 采用状态 | 所需证据 |
|---|---|
| 原样采用 | C 有可信生产来源，且与 A 内容完全一致；对应验收状态单独列明 |
| 变更后采用 | C 有可信来源且与 A 不同；展示 A→B、B→C 差异及已知修改原因 |
| 明确未采用 | 有业务撤回、作废或拒收等明确记录；保留原因 |
| 待确认采用／来源待核实 | 未取得 C、归属不明、缺可靠回执或关联存在歧义；不能统计成已采用或明确未采用 |

“变更后采用”再区分已证实人工修改、系统保存规范化、输入／素材更新、其他原因或待归因。没有人员记录时不能仅凭差异认定人为修改，更不能默认每次修改都是 AI 错误。B 与 A 相同但 C 变化时提示交接后的差异，不将其掩盖在人工审核记录中。

每条差异保留原值、新值、影响条目、运行与检查版本、修改人／时间／原因（有据才填）、生产来源、业务裁定与后续问题编号。面向人员提供简洁报告，底层采用可检索结构化记录及原文件，不仅依赖聊天记录或散落日志。

按批准版本统计原样采用、业务修改后采用、来源异常、验收失败、未确认采用、修改类型及返工投入；分母和未知项明确，避免只收成功单。经业务裁定的修正可形成回归样本，由维护人员更新新版本、独立验收再发布；不自动把生产变化写回正在运行的 Skill 或项目。
