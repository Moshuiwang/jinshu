# 生产保护与权限密钥边界

版本：v0.1｜2026-09-10｜已确认目标与开发约束；具体机制待基本方案明确后设计验证

本页维护生产保护目标与权限／密钥边界。业务交付见[产品需求](01-产品需求文档.md)，实施阶段见[行动计划](../planning/08-项目行动计划.md)，后续验证仍用 E14／E21，不另建一套编号。当前不安装安全设施、不调整现场权限、不读取真实密钥。

## 1. 要保护的用户结果

最重要的是防止 AI 对生产造成不可逆破坏，同时防止人员误指令、误选目标或借助 AI 的开发／运维能力造成同类事故。工作人员可以正常编单、生成新版本及在原系统审核；一次自然语言要求不能自动获得管理员权限，也不能解除保护。

另一层目标仍为最终在局域网独立运行、不依赖互联网。网络隔离不能代替生产动作的权限边界。详细安全架构在基本方案确定后展开，以下要求从研究工具和程序开发起适用。

## 2. 权限与误操作边界

- 业务 Agent 只得到任务必需的数据和动作。生产原件、正式播出配置、受保护程序和来源记录不能由业务身份任意覆盖、删除或修改；获准生成与交付只经限定目标的程序完成。
- 人员的自然语言请求、EPG 备注、手册内容、外部文件和模型输出都不直接成为可执行管理命令。程序核对操作、身份、任务、对象、版本和目标范围；不把自由文本拼成具有生产权限的 shell、SQL 或任意路径写入。
- 危险动作默认不在业务工具能力内。确需维护时进入独立的有权维护流程，呈现具体目标和影响，保留恢复方案；普通聊天中的“确认”“忽略限制”不能升级权限。不增加日常编单的无必要重复确认。
- 对可执行写入保留预览／校验、版本和操作记录；批量、覆盖、删除及重试的边界在实现时明确验证。验证与执行绑定同一对象和版本，不能检查 A 后实际改 B。
- 开发 Agent 可以在获准测试工作区修改程序，但不因此获得生产部署、管理员账号或现场密钥。业务运行身份不能改自己赖以受限的程序和策略；开发提交也不能靠一句对话自动放宽生产权限。

## 3. 危险密钥不交给 AI 读取

危险密钥指一旦使用即可删除／覆盖生产数据、修改权限、发布程序或控制播出等高权限凭据。真实值不放入提示、Skill、仓库、Agent 可读取的明文配置、日志、工具输出或截图；不要求人员复制粘贴给 AI。

**外置不等于隔离。**仅放在 `.env`、环境变量、被忽略的文件或同一账号可解锁的凭据库中，不能直接证明 Agent 不可读取。还要核对其 shell、文件工具、子进程、调试和宿主账号能否取得密钥；加密文件与解密能力同时可被 Agent 获取，也不构成所需保护。

设计方向是由 Agent 无权读取或修改的受控执行组件持有必要凭据；Agent 只提出结构化业务请求。执行组件独立核验最小权限及动作范围，只返回结果，不回传凭据。具体密钥存储、身份隔离和发放方式待评估，不预定某一云产品，须兼容最终局域网环境。

**隐藏密钥仍不够。**若 Agent 能通过该组件任意删库、发 shell 或调用管理员接口，即使从未看过密钥也能造成破坏；接口本身必须限制动作和目标，不能成为通用高权限代理。

按需采用短时、最小范围凭据，明确撤销与轮换；审计记录谁在何时对什么对象发起何种操作和结果，排除凭据原文。以上方向参考 [OWASP 密钥管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html) 的最小权限、生命周期和日志保护建议，具体机制尚未落地。

## 4. 程序语言与指令处理

编程语言和关键执行组件的选型纳入调研，优先评估类型约束、输入校验、内存安全、依赖维护及权限隔离支持；当前不指定语言，也不把编译、隐藏源码或混淆当成密钥保护。

自然语言只表达业务意图，真正执行使用受约束的操作类型和参数。拒绝未知动作、越界目标、未授权身份与歧义参数；数据内容不能变成执行代码。工具实现、升级和依赖变更也要能复核及回退，不因由 AI 编写就免除检查。

## 5. 任务分开与后续验证

| 执行任务 | 唯一执行者 | 输出 |
|---|---|---|
| 说明需要完成的业务事项 | 人 | 业务请求，不含危险密钥 |
| 将意图转成允许动作的请求 | Agent | 结构化参数及依据，不自行授权 |
| 核对权限与当前目标，执行允许动作 | 程序 | 执行结果或明确拒绝，日志不含密钥 |
| 决定独立维护授权或变更权限政策 | 人 | 具体授权范围；普通业务请求不能替代 |

后续 E14／E21 至少验证：AI 直接越权、人员误指令／误选环境、文件夹带恶意指令、借通用工具绕行、Agent 修改保护程序、读取或打印凭据、借看不见密钥的工具执行越权动作，以及重复／并发写入。用隔离环境与测试凭据证明允许动作可用、危险动作被拒绝；不在生产中制造破坏验证。
