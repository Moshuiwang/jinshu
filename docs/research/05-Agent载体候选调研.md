# Agent 载体候选调研

修订：2026-09-10｜v0.7｜工作入口已确定为 Codex；以下载体比较保留为历史资料

执行以[行动计划](../planning/08-项目行动计划.md)为准：线上模型跑通 MVP，再筛本地可部署模型的能力与速度下限，目标硬件实测后采购部署。各候选的公开能力为历史调研，实际选型时复核；本轮不宣称完成模型比较。资料统一见[交接清单](../planning/03-传媒资料准备清单.md)。

## 1. 当前决定与名称核对

2026-09-10 产品负责人明确确定 Codex 为工作人员主要工作界面，替代此前“Codex 为优先候选”的决定。当前转向 Skill／Plugin 与严格业务流程机制研究，不再以六种 App 比较作为工作入口定选的前置条件。现行要求以[产品需求 4.0](../product/01-产品需求文档.md#40-工作入口与流程完整性已确认待实现验证)及台账 D17／D18 为准。

以下保留此前 Codex、腾讯 WorkBuddy、OpenCode、Pi、DeepSeek Harness、千问办公（QwenWork）的历史比较，不构成并行生效的选型方案。OpenRouter 为当时口误，用户已纠正为 OpenCode。

“Pi”本轮按 pi.dev 的终端编程 Agent／Harness 调研；“千问工作”按已查到的千问办公 QwenWork 调研。两个产品身份已找到相应文档，但尚未由用户以链接再次确认。如指向其他产品，应更新比较对象。

本期首要业务目标为提高效率，减少查找素材和手工编排：自动取得 EPG＋当前素材信息 → 编单检查后交入 Output → 人员在原系统导入、检查修改并按原流程执行 → 锦书事后只读取得最终执行文件并对比。人工改后无需回锦书复检或批准；首期仍为 Playbox 完整 MVP，大洋独立能力验证。载体需配合自动取单、结果记录与浏览器状态页。比较采用系统生成耗时和编单结果，不评估人工节省；更换载体不改变质量标准和原流程责任。

## 2. 先分清比较对象

- Codex、WorkBuddy、QwenWork：现成的用户操作入口，重点验证使用体验、权限、电脑操控及离线限制。
- OpenCode：具有终端、网页等入口的编程 Agent，支持技能、工具扩展及本地模型。
- Pi：精简终端 Harness，可通过扩展和 SDK 定制业务工具与界面。
- DeepSeek Harness：插件化 Agent 运行环境，官方提供本地 Web UI，仍处开发者预览阶段。

能在 Windows 启动、能调用本地模型、能操作 Windows 图形界面、能完全断网交付，是四个不同结论。任何候选目前都没有通过本项目端到端验收。

## 4. 关键证据及限制

### 4.1 Codex

沿用同日上一轮已读取的官方 Computer Use 文档：支持 macOS 与 Windows，Windows 使用活动前台桌面。CLI 配置中的本地模型入口不证明 Desktop 插件能原样离线迁移。[A01](https://learn.chatgpt.com/docs/computer-use)、[A02](https://developers.openai.com/codex/config-reference/)

首轮复核补充：Windows 使用说明包含保持互联网连接的条件；当前自定义 provider 配置将 Responses 列为支持协议。后续须验证入口冷启动、实际模型请求和工具调用；“兼容 OpenAI 接口”不能单独证明与某个本地服务互通。传媒人员不需要参与这些配置。[A01](https://learn.chatgpt.com/docs/computer-use)、[A02](https://developers.openai.com/codex/config-reference/)

适合做现成图形操作基准；不能因为当前会话在 Mac 上成功操作飞书，就宣称 Windows ListBox、浏览器远程桌面或本地模型也已通过。

### 4.2 WorkBuddy

腾讯产品页支持授权范围内的本地文件读写和业务技能；腾讯云接入指南提供 Windows／Mac 安装入口，并展示自定义接口地址、模型名及工具／图片能力配置。[A03](https://cloud.tencent.com/product/workbuddy)、[A04](https://intl.cloud.tencent.com/zh/document/product/1300/80640)

接入指南示例使用 Chat Completions；本地服务是否支持所需请求、工具调用与必要图片输入须实测，不能仅与其他载体的接口名称相比就认定可以互换。[A04](https://intl.cloud.tencent.com/zh/document/product/1300/80640)

本轮多次无法获取专门客户端文档正文，因此不对 Windows GUI 操作细节、本地模型完全可用或离线登录作承诺。通过微信发指令到电脑执行任务，与通过 RDP／VNC 直接操作远端桌面不是同一种能力。下一步须确认客户端版本、截图／输入工具、内网模型地址和断网行为。

### 4.3 OpenCode

官方普通文档提供本地模型示例、技能发现和本地／远程 MCP 扩展。[A05](https://opencode.ai/docs/providers/)、[A06](https://opencode.ai/docs/skills/)、[A07](https://opencode.ai/docs/mcp-servers/)

Windows 文档明确可直接运行，同时推荐 WSL 以改善开发体验。[A08](https://opencode.ai/docs/windows-wsl/)

工程判断：很适合调用独立的扫描、编排、生成和校验工具。若需要点击 Windows 应用，仍须额外选择操作组件；WSL 可访问文件不代表可直接控制 Windows 桌面。

发现官方另有 v2 beta 文档，与普通版本安装方式不同；该 beta 明确存在发行方式限制。试验必须固定版本与对应文档，不混用配置。[A09](https://opencode.ai/v2/docs)

### 4.4 Pi

官方定义为可扩展的精简终端 Harness，提供技能、扩展和 SDK，可嵌入自定义界面。[A10](https://pi.dev/docs/latest)、[A11](https://pi.dev/docs/latest/sdk)

官方 provider 文档明确覆盖本地模型服务；Windows 文档给出 Git Bash 和可选 PowerShell 工具路径。[A12](https://pi.dev/docs/latest/providers)、[A13](https://pi.dev/docs/latest/windows)

官方特别说明没有内置沙箱，权限继承自运行用户，隔离需要操作系统、容器等机制承担。[A14](https://pi.dev/docs/latest/security)

因此它适合可控的专用工具调用，但不能把精简理解为工程控制已经齐备。需补用户交互、权限隔离及图形操作组件，不能直接把终端交给传媒人员就视为产品交付。

### 4.5 DeepSeek Harness

官方首页、官方仓库明确其为插件化开源 Harness；模型、工具、技能、会话和 UI 可组合，当前开发者预览仍会发生兼容性变化。[A15](https://www.deepseek.com/harness/en/)、[A16](https://github.com/deepseek-ai/deepseek-harness)

官方 provider 文档允许公司网关和自托管模型服务；工具目录包含 Windows PowerShell 能力。[A17](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)、[A18](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-catalog.md)

它有明确的本地定制空间，但不能由“可以编写插件”推导出“已经拥有可靠 Computer Use”。浏览器显示其 Web UI，也不等于能控制浏览器中的另一个远程桌面。需固定源码／发行版本，验证任务状态、确认、工具权限和离线依赖。搜索中出现的社区桌面封装，不作为官方客户端能力依据。

### 4.6 千问办公 QwenWork

官方帮助中心有技能、连接器和电脑操控说明；Windows 安装要求写明 Windows 10 64 位或更高、x86_64，以及互联网连接。[A19](https://qwenwork.cn/docs/desktop)、[A20](https://qwenwork.cn/docs/install/windows)

电脑操控专页提供截图、点击和输入流程，但系统要求只列 macOS 14+。因此当前不能依据 Windows 安装包推定 Windows 图形操作已支持。[A21](https://qwenwork.cn/docs/desktop/computer-use)

已读模型选择页描述产品提供的模型选项，未取得接入自托管模型的证据。[A22](https://qwenwork.cn/docs/desktop/model-selection)

可作为办公交互及 Mac 方案观察对象；Windows GUI、本地模型和断网能力待补证。网站中的“后台执行”“像素级”等描述属于产品说明，不作为本项目性能验收结果。

## 5. 本项目的建议选择策略

以下为工作入口定选前的历史筛选方法；Codex 主界面已确定，后续复用工具与验证经验，不继续按本节重选人员入口。

1. **提前筛选离线条件。**样本研究时对少量候选做 E10 最小断网验证：重启入口、调用内网模型与固定工具、呈现并保存人员选择、恢复后读回；需要 GUI 的候选追加操作验证。使用现有或借测条件；线上 MVP 无须等待该验证完成，但采购定选及完整本地版本建设前必须通过，最终设备部署后再做完整离线验收。
2. **固定可迁移的业务工具。**扫描、有效时长计算、PLY 生成和检查尽量独立于 Agent，状态页读取同一套任务记录。规则已确定的条目不逐条重复确认；不为载体选型追加人工效率对照。
3. **文件路线成立时收敛少量组合。**OpenCode、Pi、Codex 与 DeepSeek Harness 按离线条件、人员使用体验、工具正确性、任务恢复和维护成本筛选，先验证最有依据的组合，避免一开始深度改造全部框架。
4. **确需 GUI 时比较完整成本。**Codex 可做已公开能力的基准，WorkBuddy 先补目标 Windows 操作证据；其他载体明确额外组件与人员接管成本。在线基准成功不等于最终离线候选通过。
5. **Mac 远程路线单独试验。**验证远程画面、可靠输入、保存结果、授权与重连；不能按“支持浏览器”直接打勾。
6. **按完整任务决定交付。**后续仍执行 E07 全流程离线验收，以及独立验收样本、交接环境访问和故障恢复检查。选择满足生成质量、系统耗时、状态展示与维护条件的组合，再以真实负载适配硬件。

PLY 直接生成优先、批量导入其次、必要时 GUI 操作的探索顺序仍保留，见上一份调研。当前无证据支持宣称某个候选全面优于其他候选。

## 6. 用同一份任务做后续验证

| 验证项 | 通过证据 |
|---|---|
| 输入与工具调用 | 从约定来源自动取得 EPG、保存本次输入版本，调用指定扫描和生成工具，检查后交付 Output；自动获取能力按 E18 验证 |
| 人员确认 | 显示原 EPG 条目、候选差异、依据与影响；待解决与仅供知悉分开；可更正选择，退出和恢复不丢确认 |
| 业务结果 | 同一规则下，使用区段、有效时长和必要事件正确；PLY 通过独立检查、目标环境访问及 Playbox 人工审核 |
| 两个主指标 | 能按验证计划第 6 节记录收到 EPG 至 Output 的耗时及执行单一致／差异；不统计人工耗时或节省比例 |
| 浏览器状态页 | 任务记录可供大屏自动刷新，状态、最近更新时间、异常和恢复结果正确；具体交付见产品需求第 4.4 节 |
| GUI 附加项 | 正确操作目标 ListBox，处理窗口、弹窗、停止和保存；批量导入与逐条插入分开测 |
| 远程附加项 | 原机加密狗授权、会话、键盘、分辨率、重连及结果核对均通过 |
| 失败控制 | 工具失败不口头报成功；补料后可显式继续，取消后停止；恢复时显示已完成范围与人工接管方式 |
| 原流程交接与事后对比 | 人员导入原系统、检查修改并确认后按原流程执行，无需回锦书放行；事后只读取得最终执行文件，关联 EPG 与原产出自动比较，实际采用身份按 E16 验证 |
| 权限 | 素材只读、待审核位置可写，不获得正式发布能力 |
| 最小离线与兼容 | 早期 E10 通过；实际请求、工具调用与必要图片输入互通，不以“接口兼容”描述代替实测 |
| 完全离线 | 后续 E07 禁止互联网后冷启动并完成任务，本地模型及所需操作组件均可用 |
| 版本与维护 | 可固定版本、导出任务证据、复现问题，并有明确维护责任 |

文件路线与 GUI 路线所需模型能力不同，最低模型不能混为一个指标。先在相同工具、数据及规则下比较；若模型或操作组件无法相同，应分别记录原因，不能把整套组合差异全部归因于 Agent。

## 8. 来源、检查与历史
