日期：2026-09-10｜v0.8｜统一线上验证到采购部署顺序，非采购定单

2026-09-10 更新：先线上模型跑通 MVP，筛选业务能力与速度的最低可接受要求，再通过候选硬件实测、预算评审和采购，搭建本地 LLM 并完成离线验收。详见[行动计划](../planning/08-项目行动计划.md)。下文具体模型、价格及配置资料为 2026-09-08 的历史调研，本轮未刷新，不作为当前定选或报价；实际选型时重新核实。

## 1. 已确认要求

- 最终在不连接互联网的内部局域网运行；域名、固定 IP 等由公司自行管理。
- 两台模型主机合计争取控制在人民币 100,000 元，最高预算为 200,000 元；双机热备要求不变。
- 两台机器预先加载模型。主机故障后自动切换，允许短暂停顿与步骤重试；保留已确认任务进度，不重复交付。
- 样本研究时并行做最小断网验证，先排查入口、组件与本地工具的基本可用性；用现有或借测条件，不先采购最终设备。线上完整流程和模型比较继续开展，依据生成质量、系统耗时和实际负载适配硬件，最终做完整离线验收。
- 配置按锦书生成质量、系统耗时和负载选择，执行单对比用于持续了解结果。模型候选保留千问 3.8 Flash、DeepSeek V4 Flash，也允许增加更合适的候选；不要求提供人工节省率来证明配置。

按产品负责人最新调整，本轮预算只比较两台模型主机完整配置，不为网络、UPS、备份介质或费用预留单列额度。网络与供电条件仍作为部署要求记录，并非默认已经落实。现有网盘、Windows／Playbox 终端及授权按复用条件单独确认；若发现额外采购依赖，列出事实供另行决策，不自行扣减本轮主机额度。

## 1.1 硬件与模型选型背景【不是项目需求或扩展计划】

产品负责人补充：这笔内网 AI 设备投入未来可能服务于视频内容检查，以及对疑似问题片段进行剪除或遮挡等简单编辑，也可能通过操作现有剪辑软件完成。这些信息仅用于解释设备的潜在长期用途，帮助比较模型和硬件，不构成视频模块立项、交付承诺或验收要求。

选型时可兼顾：视觉模型适配、视频解码与编码能力、常见剪辑软件的运行条件、内存与存储扩展空间，以及模型运行与其他计算任务的资源分配。对比中应分别说明“满足当前编单所必需的配置”和“兼顾未来用途的可选投入”，不因未来设想强制增加配置，也不承诺所选设备已经满足尚未定义的视频任务。

当前不设计视频审核流程、不选定剪辑软件、不制定内容审核规则、不增加视频测试和开发任务。未来若实际开展，需要另行明确需求和授权。当前范围为自动取得 EPG，与当次素材信息生成并检查待审核 PLY 后交付 Output；人员在原系统审核执行，最终执行文件事后只读取得并对比，预算及双机热备要求保持不变。

## 3. 容量：文件大小只是下限

| 对象 | 本轮取得的数据 | 解释 |
|---|---|---|
| DeepSeek-V4-Flash 官方混合精度权重 | 权重索引 total_size = 159,609,485,896 字节，约 159.6 GB／148.6 GiB | 尚未加推理缓存、引擎工作区、系统和其他模型 |
| Flash-Next 原权重 | 索引 total_size 约 360 GB | 显然不能直接放入普通 64／128GB 单机 |
| Flash-Next FP8 仓库 | API usedStorage 约 185.6 GB | 是仓库存储统计，不是运行内存，不能作为精确显存数 |
| 27B 简化算术 | 16 位约 54 GB，8 位约 27 GB，4 位约 13.5 GB | 仅按参数位宽的理论权重估算；混合精度、视觉模块、元数据及工作区使实际占用增加 |

**两台机器各自必须能独立承担故障后的工作量。**把模型拆在两台机器上共同运行，属于分布式推理，失去任一台可能就无法推理，不是双机热备。两张卡装在一台主机中也不是双机冗余。

不能将“权重装得下”当成“可用”：需要测首响应、整单时间、上下文长度、并发、视觉输入、温度与长时间运行。缓存随请求形态变化，本期不要求为标称百万上下文直接采购，应先通过检索与分批处理控制输入长度。

试算前采集日单条目量、任务频率、集中交单时段、相关素材目录规模和交单截止时间，记录收到 EPG 至 Output 的系统耗时；扫描、信息读取及模型请求可作诊断分段，不计后续人工审核用时。单活、单任务仅是当前试算假设，不能用于证明繁忙时段容量；推广负载另行验证。

## 6. 内网部署结构

```text
EPG 约定来源 → 编单任务协调／必要人工确认
          └→ 任务状态与结果记录 → 内网浏览器大屏（自动刷新）
          │
     稳定的内网模型地址
          │
  主模型服务 A ←故障切换→ 备用模型服务 B
     均预加载同一已验收模型、配置与工具版本
          │
  EPG 输入、任务记录、人工确认、原产出与 Output
  独立版本与原产出检查记录／最终执行文件与差异档案

模型服务只负责推理；有副作用的工具由单一任务执行权控制。
EPG 与网盘素材只读；Output 可写；人员在原系统审核执行。最终执行文件事后只读取得，不要求返回锦书放行。
```

### 6.1 IP、域名与入口

| 资源 | 要求 |
|---|---|
| A／B 主机 | 各自固定 IP 或静态租约；独立主机名 |
| 稳定服务入口 | 公司内部域名指向高可用入口，Agent 不绑定某台模型主机 |
| VIP 方案 | 若平台及网络支持漂移，可用同网段虚拟 IP；切换需验证 ARP／交换机策略 |
| 代理方案 | 不适合 VIP 的平台可用双实例入口代理；代理自身不能是唯一单点 |
| DNS | 内部 DNS 可解析；具备冗余或经批准的备用解析方式 |
| 时间 | 使用内网时间服务，便于审计和过期判断；不能依赖互联网时间源 |
| 证书 | 内部 CA 或公司认可证书，全链路正常校验；证书更新须可在内网完成 |

不在未获网段信息前编造真实 IP。DNS 只负责名字解析，修改 DNS 记录并不保证即时热切换，客户端缓存和长连接必须处理。VIP 软件与操作系统需实际适配，不把 Linux 的实现直接假定可在 Mac 上原样运行。

### 6.2 网络容量与访问

- 模型请求／响应、心跳和任务记录流量通常与视频复制不同，应实测评估。1GbE 可作为低并发模型请求的起点，10GbE 优先用于已有素材网盘读取或较大同步；不把 10GbE 无条件列为模型热备必需。
- 两台模型权重放各自本地 SSD，避免每次启动都从同一网盘拉取大型权重。升级时校验文件与模型版本。
- 只读扫描限制目录与并发，优先读取元数据。若提取时长需要访问视频内容，评估对生产存储的实际负载，不全量复制视频。
- 使用缓存时须在本次任务中确认素材身份与信息仍有效。任务界面显示已扫描范围、不可读取项和下一步，不能让人员长期等待而不知道进度。
- 根据最终组件编制端口表：内部 HTTPS／模型 API、任务同步、健康检查、DNS／时间及必要 SMB；若使用远程桌面，再限定 RDP／VNC 的来源和目的，不全网开放。
- 若要求抵御交换机或电源故障，需双交换路径、独立供电／UPS 或复用已具备冗余的基础设施。单交换机、单网盘、单 Agent 主机的故障不能由模型双机自动覆盖。

## 7. 热备切换和任务恢复

本节列出恢复控制要求和候选实现。最大允许暂停、接管时机及具体组件待联合确定；已确认的“保留已确认进度、不重复交付”继续作为验收要求，不以尚未指定数值降低该要求。

1. **备用机真正就绪**：模型加载完成，周期性执行小型推理与必要工具检查。进程活着或端口打开不足以判定可接管。
2. **任务有持久状态**：保存 EPG、素材快照、规则版本、人工选择、已确认编排及生成阶段。确认只有持久写入并达到选定复制要求后才向人员回报成功。
3. **单一执行权**：使用租约／仲裁及隔离旧主机制。网络分区时不能让两台都自认为主机；宁可暂停带副作用操作，也不能重复执行。
4. **模型请求可重试**：主机故障时丢弃未完成的响应，以保存的任务状态重新请求；不承诺搬运进行中的推理缓存或逐 token 无缝续接。
5. **副作用不可盲重放**：PLY 采用任务编号和独立输出、完成后提交标记；不把半文件当成已交付结果。重试前检查已有状态。
6. **GUI 必须先检查再恢复**：如果原 Windows 仍运行，需先核对已插入条目和保存状态，停止旧控制端，再允许新端继续。不能让两个 Agent 同时操作同一 ListBox。

纯双节点在网络分区时难以仅靠互相心跳安全决定谁继续。建议复用独立仲裁位置／第三个轻量见证节点，或采用可验证的旧主隔离机制。见证不承担模型推理，但其故障策略和部署位置要明确；本轮不为其单列预算额度。

“不丢已确认进度”是对持久化记录和确认时机的要求；不是只装一个负载均衡器即可满足。具体数据库／复制实现需工程设计，不把共享文件夹当作天然一致性方案。

### 7.1 人员看到的恢复与接管

| 时机 | 人员体验与责任 |
|---|---|
| 故障刚发生 | 显示“正在恢复”、已完成范围和保留的确认，避免继续展示过期的成功状态 |
| 恢复成功 | 从可确认的保存进度继续；受影响的素材与编排重检，必要时请人重新确认 |
| 超过约定等待时间 | 明确提示交回人工的步骤、仍需完成的部分和维护联系人；避免让人员判断哪台主机故障 |
| 已经生成或交付过文件 | 显示文件位置与版本，重试先查已有结果，不重复交付或覆盖历史文件 |
| 需要图形操作接管 | 先停止旧自动控制，核对原 Windows 中已插入与已保存内容，再允许人或恢复端继续 |
| 人员回来继续任务 | 保存的选择仍可读；同一 EPG 任务补料后显式继续，换版 EPG 按新任务处理 |

试运行前由业务、技术与维护人员根据交单截止时间及人工补救时间，约定最大等待、接管时机、联系途径和升级后复验责任。具体姓名与时限填入[台账](../planning/07-产品决策与验证台账.md)，当前不编造分钟数。恢复验收须让真实使用者按指引完成接续，而非只由运维确认服务切换。

## 8. 高可用边界

| 故障 | 模型双机能否直接解决 |
|---|---|
| 主模型进程／模型主机失败 | 在备用健康且切换机制有效时可恢复推理 |
| Agent／任务协调进程失败 | 需其自身能恢复、持久状态可读；不能只备份模型 |
| 输入／状态存储失败 | 需冗余或可接受恢复策略，模型双机本身不能解决 |
| Windows ListBox 电脑或加密狗失败 | 模型双机不能解决，仍需人工原流程或第二套获准终端 |
| 整个网盘／单交换机／单供电失效 | 需基础设施冗余；当前不能承诺全链路无单点 |

因此“模型双机热备”和“整个编单服务高可用”必须分别验收。若最终走直接 PLY 生成，Windows 编单终端不必参与自动生成，故障面更小；人工审核所需客户端仍要可用。

## 9. 采购前的验证与询价要求

用户提供业务时限与已有负载情况；模型 token、首响应、生成速度、整单耗时和资源要求由项目实测，不能要求用户猜数。资料与现场约束统一见[交接清单第 5—7 节](../planning/03-传媒资料准备清单.md)，不另行索取原始视频或联系人。

1. 先完成线上 MVP，再冻结流程、工具和规则，比较可本地部署候选的相同编单样例，包含歧义和异常，形成能力与性能需求。记录精确模型、精度和推理配置；E10 用现有或借测环境在采购定选前通过，不阻止先开展线上 MVP。
2. 记录真实工作量、目录规模、上下文、图片使用量、并发及整单时限。暂按单活、单任务试算，推广容量另算；记录锦书自身的生成耗时及任务等待原因，不用模型响应速度替代完整系统耗时，不记录人员实际投入。
3. 对候选硬件借测／供应商演示：模型加载、首响应、生成 token/s、请求规模、整单完成时间、工具调用、GUI 如需要、约定并发、持续运行和内存峰值。以业务时限判定，不套用线上速度；精度改变后复核质量。
4. 验证另一台关闭时，每台模型主机仍能独立完成约定负载；确认必要的重启、模型加载和运行条件。采购前不要求建成完整任务状态复制、恢复界面或人工接续功能。
5. 验证断网冷启动与身份／许可证依赖，备用已加载并不代表重启后仍可离线启动。
6. 采购前明确恢复目标、方案及依赖；第 7、7.1 节的完整任务故障切换、存储异常、已确认记录保护、恢复显示和人员接续，在本地完整版本部署后、试运行前演练。
7. 主机询价包含含税整机、内存／SSD、显卡准确型号、整机散热电源、交期和保修；UPS、网络与见证设备只记录部署依赖，本轮不单列费用。供应商须注明实际支持的模型精度与引擎版本。

当前尚缺完整配置报价、目标负载和设备实测。按“10 万争取、20 万封顶”评估实际筛选出的合格候选，不局限于历史三个型号，不以容量推算代替验收或报价。

采购定选须有完整配置报价及真实负载借测证据；生产试运行须完成完整离线、交接环境和恢复验证；推广依据生成质量、系统耗时、实际执行单对比与交付条件，不要求人工总投入下降证明。三个阶段分别记录结论，不把公开参数或采购完成等同于业务验收。

## 11. 新增恢复边界：版本与采用证据也必须保留

故障切换和任务恢复须固定原任务的实际执行版本，不能因备用节点已升级而悄然换版。EPG 输入、独立来源记录、锦书原产出及其检查记录、最终执行文件快照和差异事件均纳入恢复设计；缺证据时保持待核验，不补写成功。

业务 Agent 不得写这些证据的正式存储或持有发布／验收签名材料。入口、原产出检查和最终文件只读取得组件的权限及恢复策略须与模型服务分别验证，双机模型切换本身不证明它们已受保护。生产回读和对比记录采用任务与提交身份避免重复归档；多个正式文件版本分别保留。

评估新增存储容量、保留期限、恢复与维护负担，沿用两台主机预算口径；如有额外设备或部署依赖另列事实供决定，不擅自修改预算。验证要求由 E14—E16 及 E13 承接。
