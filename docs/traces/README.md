# Trace：连续工作与接手方法

状态：锦书轻量方法 v1，2026-09-10。参考 [Lingxi #678 v19](https://github.com/Moshuiwang/lingxi/issues/678)，只采纳本文件列出的规则；上游修订不自动改变锦书方法。

Trace 是连续工作与交接记录。多个工作项存在顺序依赖、跨任务接力或复杂现场交付时使用。单个范围明确的 Issue 不建 Trace。当前只建立方法，不代表任何 MVP 执行合同已获批或已开工。

每次用 `docs/traces/<Issue号>-<短名>/`，对应 `[tracking]` Issue 只放目标、文件链接和当前阶段；不重复维护 Issue 状态链。

| 文件 | 职责 |
|---|---|
| 合同.md | 本次结果、范围、不做事项、授权终点、进入条件、步骤和验收依据；修改范围、权限或验收标准须重新批准 |
| 任务表.md | 实际进展和恢复点，只在状态变化、决定、交接或结束本轮工作时更新 |
| 验收.md（按需） | 跨工作项新增断言或集中证据索引；能链接成员 Issue 时不另建 |

合同用一段用户结果、一张步骤表和实际命中的例外即可。只链接既有产品规则，不复制；没有外部写入、共享资源或跨任务接力时不建空表。与本次无关的工具教程、模型配比、长期监控和额外角色不进入合同。

步骤表至少包含：步骤、可观察产物、Ready 条件、负责人／工作区、通过证据、完成后进入哪一步与失败去向。开始执行前，至少一个步骤应为 Ready（所需条件齐备）；其余步骤写明缺什么。可以先建记录、整理依赖和准备资料，这不等于已经开工。依赖说明传递的资料或产物，避免互相等待而无法推进；本次授权不能从方法模板、历史聊天或上游仓库推导。

任务表顶部保留三行：

- 当前：正在做的步骤、实际候选和最后通过证据。
- 下一步：下一项可执行工作、负责人和入口。
- 等待／占用：缺什么、谁补齐、仍占用什么资源、如何释放；无则写无。

步骤状态为 pre-ready（准备中）、Ready（可执行）、执行中、等待、完成；与 Issue 主状态分别记录，后者按[协作约定](../协作约定.md)维护。只有条件已齐备的步骤才能开始执行。已批准范围内持续完成，范围或权限变化只停止受影响部分。执行者自查不冒称独立审核；采用独立审核时固定候选，由未参与实现者给出结论。

交接先保存共享证据，继任者确认合同和恢复点，旧执行者停止写入后转交；未确认接管不宣称交接完成。外部查询失败不等于任务完成。任何周期观察须有用户明确授权、真实运行机制、失败提示和停止条件。

结束本轮工作记录实际到达的授权终点、验收证据、未完成去向及临时资源清理。提交、合并、现场部署与实际采用分别陈述；MVP、采购、本地交付不在一个模糊批准中自动贯通。
